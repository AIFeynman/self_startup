UnfoldX 从交付视频到交付结果：能力补充设计

  • 日期：2026-11-20
  • 状态：Draft（讨论稿，未排期）；2026-11-20 修订：抖音归因改为平台组件 + 视频专属关键词，发布前打分改为内部挑选；新增第 6 节逐环节能力设计；第 6 节并入四维 17 项作为共用评估语言；第 4 节结果类型合并为三组

1. 结论

现有链路“选题 → 补素材 → 跟进 → 做视频 → 发布”是生产流水线，交付止于“发出去”。用户付费看的是发布之后：流量、成交、留资。

要直接交付结果，需要把流水线改成围绕一个指标运转的闭环：定目标 → 挂转化 → 收数据 → 按数据改下一条。视频只是闭环中的一环。

反馈数据难拿是最大难点。解法是不依赖平台开放接口：站内引导一个可标记的动作（平台组件、视频专属关键词），结果从平台后台或我们的系统里取，再连回视频；流量数据由用户授权，从他们自己的后台拿。

3. 目标能力：6 层

层 现在 目标 交付物
1. 目标契约 用户给一个主题 每个账号或计划先定 KPI（涨粉/播放、GMV、留资数），并定预算和周期 目标卡，Agent 的所有取舍对着它
2. 结果导向选题 热点和资料驱动 三个来源：搜索需求（平台搜索词、下拉词）、同行爆款拆解（钩子、结构、评论区痛点）、卖点映射；选题卡写预估播放和转化 带“为什么能拿结果”的选题卡
3. 转化型内容 讲清楚、好看 按目标切换脚本骨架；行动指令写进分镜、字幕、置顶评论和封面 视频 + 封面 + 标题 + 置顶评论一整套
4. 转化挂载 无 带货：商品卡/橱窗/推广链接；线索：资料包钩子、表单落地页、企微活码 每条视频都有可统计的转化入口
5. 跟进升级 跟进视频 跟进人：评论和私信关键词回复、自动发放资料、意向分级、线索推送到 CRM 或飞书多维表 线索表：谁、来自哪条视频、意向几级
6. 数据回流与迭代 无 发布后第 1、24、72 小时取数；留存曲线对齐分镜，定位掉人的那一拍；归因到选题、钩子、风格；自动生成下一轮 A/B 每周结果报告和下一批选题

脚本骨架按目标区分：

  • 流量：钩子 → 反常识 → 爽点。
  • 带货：讲透原理 → 建立信任 → 自然推荐 → 行动指令。
  • 线索：给一半价值 → “评论 XX 领完整版”。

第 6 层是差异点：UnfoldX 的视频逐镜头生成，镜头级留存归因和定向重做是通用成片工具做不到的。

4. 结果类型：合并为三组

结果类型很多，但反馈怎么拿、评估看什么、改进改哪里，可以合并成三组。每组共用一套做法，第 5、6 节按组取用。

组 包含的结果 典型领域 反馈获取 评估核心项 改进重点 优先级
注意力 流量涨粉、平台收益、宣传知晓 各领域起号、政务公益 插件同步后台（5.2） T1、T3、P1、E2、P4 选题和开头，掉人镜头 第一阶段并行，只承诺过程
转化 线索留资、资料领取与私域、知识付费（课程、训练营、直播预约）、带货、咨询到店、招聘 考试教育、职业技能、B2B、专业服务、图书 平台组件 + 视频专属关键词 + 订单或留资数据（5.1） M2、E4、T2、行动指令、合规 证据素材、行动指令、转化物料 主线：先做资料领取 → 私域 → 报课；带货放第二阶段
学习效果 课堂教学、企业内训、客户教育 K12、培训、企业 看完即测、完课、工单量，在自有或客户平台 E3、E4、E5、M1 讲解结构和解释连接 校准线：结果最好证明，并为 E 维提供真实分数
  • “授课”分属两组：用短视频卖课归转化组，用短视频教学归学习效果组。
  • 学习效果组的测验正确率是 E3 的直接测量，用来校准注意力组和转化组的预估。
  • 暂缓：财经（不能荐股）、医疗（广告合规严）、政务（结果难测）。
  • 待核实：外部课程平台订单能否对接；直播预约数据是否带来源视频。

5. 反馈数据获取方案

5.1 转化归因：站内引动作，站外或后台记结果

抖音限制站外导流，视频和评论里放外链、二维码一般会被限流或删除，所以短链不是抖音上的主方案（平台规则常变，具体能力需实测核实）。链路改为：站内只负责引起兴趣并引导一个动作，留资和成交落在平台组件或我们的系统里，再靠口令或后台数据连回视频。

按可靠程度排列：

方式 做法 归因精度 前提
平台内组件 + 读后台 线索：企业号表单、小风车等线索组件；带货：商品卡、橱窗。留资和订单在平台后台带来源视频 最高，到视频 多需企业号或带货资质；数据由插件从后台同步（见 5.2）
视频专属关键词 每条视频一个口令（如“评论或私信回复 A1 领资料”），自动回复发放资料或表单，口令即来源 高，到视频和版本 需要私信自动回复能力；限速防营销风控
专属优惠码 “下单填 A1 减 10 元”，用于自有店铺或课程 中高 用户有自有成交渠道
时间窗 + 自报来源 视频发布后数小时内新增留资计给它；表单预填“从哪条视频看到的” 低，只看趋势 无，作为兜底

按平台选择：

平台 主方案
抖音 平台内组件 + 视频专属关键词
允许外链的平台（B 站、YouTube、公众号等） 我们托管的领取页、表单、企微活码，每条视频独立参数的短链

最硬的交付仍是可核对的明细：“本月带来 213 条留资，每条来自哪条视频、哪个版本，见此表”。

5.2 流量数据从用户自己的后台取

  1. 浏览器插件同步创作者后台（推荐）：用户已登录创作者后台，插件只读本人作品的数据，定时同步，包括作品分析中的观众留存曲线（各平台可读字段待实测核实）。
  2. 公开数据兜底：作品页公开的点赞、评论、收藏数，作为热度近似。
  3. 截图识别兜底：用户上传后台截图，模型识别成结构化数据，永远可用。

5.3 数据少或延迟时

  • 发布前打分：内部挑选，不让用户改。“自己生成的片子为什么打分不好还要改”这个悖论，出在把打分当成交给用户的质检。正确用法：
  • 生成一次只是一个样本，比较几个版本谁更好要稳定得多。内部对钩子、开头、封面各出 N 版，打分挑最优，用户只看到挑出的版本和备选。
  • 打分能用上生成时不易用好的信息：本账号历史留存、同行近期爆款、平台当前偏好。爆款拆解来自 offline/lab/viral_analysis。
  • 反复扣分的问题（如开头 3 秒无冲突）写回模板和提示词，下次直接生成对。打分是改进生成器的信号。
  • 只做相对排序，不预测绝对播放量；用真实回流数据持续校准。
  • 对用户的说法：“已从 5 个开头里挑出留存预估最高的；另 2 个可作 A/B 备选”。
  • 小流量测款：用打分排在前面的 2–3 个版本分批发布或小额投流，用先回来的数据挑赢家再放量。投流花钱，每次由用户确认。

6. 逐环节能力设计

原则：每个环节多产出两样东西，对结果的预估和可归因的标签，并用统一的内容 ID 把选题、钩子、镜头、发布版本和结果数据串起来。

现状对照：

模块 现状 缺口
选题 video_worker/topic_library.py 接 learn_evolve 选题台，新闻和事件为源，分数是编辑分 没有平台用户需求信号，没有结果预估
审片 skills/video-review 事实、视觉、运动、声音的制作质量 不看平台表现（抓人、掉人、平台规范）
爆款拆解 skills/breaking-down-viral-videos 单条视频拆解成片 结论没沉淀成可复用、带实测表现的钩子库

6.0 共用底座

表 内容
内容基因 选题类型、需求来源、钩子类型、讲解骨架、风格模板、时长；每个镜头的功能（钩子、冲突、证明、行动指令）；四维 17 项的档位与依据（见下）
结果表 按作品 ID 和版本：播放、3 秒留存、完播、留存曲线、互动、口令回复、留资、成交

没有这三张表，后续的预估、审片和归因无法连起来。

共用评估语言：四维 17 项

沿用 growth-engine 的视频内容四维体系 v1.10，不另起一套。预估、分析、归因、改进四件事用同一套维度，结论才能互相写回。

维度 项 主要在哪个环节产生和修改
选题 T T1 关注理由、T2 回报承诺、T3 认知缺口、T4 感触／交流理由 6.1 选题
素材 M M1 信息增量、M2 证据分量、M3 独特获取价值、M4 体验承载力 6.2 补素材
讲解 E E1 回报兑现、E2 观看推进、E3 理解建立、E4 应用形成、E5 转述形成 6.3 讲解
呈现 P P1 入口表达、P2 内容适配、P3 体验塑造、P4 编排融合 6.4 生成

使用规则（取自原体系）：

  • 每项 0–4 五档，每条观察只登记一个主要归属，不重复加分；开头是位置，不是第五个维度。
  • 按目的定核心项：传播、理解、判断三种目的的核心项不同，先定目的再评；M2 证据分量不随目的降低。
  • 17 项是机制候选，不是爆款配方；未出现不扣分，出现也不自动加分。

把四维连到结果：原体系的作用链是“四维特征 → 观众反应 → 行为环节 → 结果”。行为环节对应结果表里的指标：

行为环节 结果表指标 主要相关项
进入 封面点击、3 秒留存 T1、T3、P1
持续观看 完播、留存曲线 E1、E2、P2、P4
收获／满意 收藏、正向评论 T2、E3、E4、M1
传播 转发、评论区讨论 T4、E5、M4
关系／行动 关注、口令回复、留资、成交 M2、E4、行动指令

这张对应表是预估和归因的连接点，也是要用真实数据校准的假设。

6.1 选题：接入平台用户真实反馈

能力 做法 写进选题卡
需求证据 挖评论区：本账号和同行视频下的高赞提问、“没听懂”“求讲”；平台搜索词和下拉词 多少人在问，附评论原文
供给缺口 同一问题已有视频的数量、质量、时间 红海还是空白
转化匹配 选题与资料包、商品、服务的关联 能挂什么转化
预估区间 同类选题在本账号和同行的历史表现 播放区间、留资区间
事后校准 发布后对比预估与实际，修正估算 预估准确率

评论区由插件读取（见 5.2）。爆款拆解回答“别人怎么做成的”，评论区回答“用户卡在哪”，后者对选题更关键。

按学习、传播、工作三类目的怎么选题、出什么形态和配套，见 2026-11-20-topic-agent-purpose-design.md。

选题卡按 T1–T4 加 M1、M2 评分，口径沿用 2026-11-07-topic-quality-by-purpose.md。评论区需求证据主要抬高 T1 和 T3 的依据，从“推测受众在意”变成“有 N 条评论在问”。

6.2 补素材：补“让人信、让人动”的素材

  • 信任证据：实测截图、对比、数据出处，带货和线索类最需要。
  • 异议素材：评论区的常见误解和质疑，讲解中主动回应。
  • 转化物料：从讲解素材自动生成资料包 PDF、清单、模板，作为留资钩子。
  • 素材缺口检查：列出脚本中无证据支撑的说法，生成前补齐或删掉。
  • 按 M1–M4 检查：没有增量（M1）、证据只有结论和来源标签（M2）、缺少普通介绍拿不到的内容（M3）、缺少能承载体验的细节和过程（M4），各自对应补什么素材。

6.3 讲解：在文本层先做多版本筛选

  • 钩子库：爆款拆解沉淀为钩子和骨架库，每项带本账号实测表现；讲解从库中选。
  • 文本层变体：讲稿和分镜阶段出 3–5 个开头，成本几乎为零。
  • 讲解预评估（不渲染），按 E1–E5 加两项结果导向检查：
  • E1 回报兑现：开头承诺的回报有没有实质兑现。
  • E2 观看推进：每段是否推进问题或处境，掉速段落在哪。
  • E3 理解建立：模拟受众 Agent 复述，复述不出即没讲清。
  • E4 应用形成：结论能否落成可执行的判断或步骤。
  • E5 转述形成：有没有可独立准确转述的表达。
  • 钩子强度（T1、T3 在开头的落地）：前 3 秒有无冲突或利益点。
  • 行动指令是否自然、合规（极限词、功效宣称）。
  • 每拍标注功能，供镜头级归因。

6.4 生成视频和图文：审片增加平台表现维度

评估项 对应四维 现有 video-review 需要补
事实、视觉、声音 基础检查 已有 —
前 3 秒抓人、封面和标题 P1 入口表达 部分 首帧可读性、字幕钩子、画面变化；封面标题出多版并做点击预估
关键内容是否被展示 P2 内容适配 部分 关键结构、关系、变化是否直接揭示，而不只是装饰
体验是否承担回报 P3 体验塑造 部分 视听选择是否对应内容，不凭“大片感”判断
掉人风险点 P4 编排融合 无 静止过长、信息断档、节奏骤降，定位到镜头
平台规范 执行约束 无 字幕安全区、低质或 AI 拼贴判定风险、站外导流违规

基础检查（字幕清楚、无技术错误）只说明合格，不解释表现；P1–P4 才提出影响行为环节的机制假设。

  • 问题只重做对应镜头，不重做整片。
  • 图文与视频共用讲解骨架，一次产出多形态；小红书单独评估首图点击、标题和正文结构。
  • 提效：淘汰放在尽量早的环节（文本 → 静帧 → 局部渲染 → 整片），只渲染胜出变体；A/B 只换开头 3–5 秒，后段共用。

6.5 发布后跟进：跟进人和续作

  • 评论、私信关键词回复，意向分级，线索进表（见 5.1）。
  • 评论反哺选题：新出现的提问直接生成续作选题卡。
  • 爆款放大：数据超过预估时，自动提议续集、系列或换角度再讲。

6.6 归因与优化：三层

层 回答什么 方法
镜头级 哪一拍掉人 留存曲线对齐分镜
选择级 哪种选题、钩子、骨架、风格更好 跨作品对比内容基因；同选题 A/B 因果最干净
效率级 哪个环节投入值不值 环节成本对比结果贡献：如精细路线成本高而结果不更好就降级；预估长期不准的评估项砍掉

四件事如何共用四维：

任务 做什么 输出
预估（发布前） 按四维出画像，找强项和短板，用于版本间相对排序（见 5.3） 四维画像、主要短板、排序理由
分析（爆款拆解、本账号复盘） 结果表上表现突出的环节，回到四维找候选机制，并和普通作品对比 主驱动候选、条件、反例
归因 结果指标 → 行为环节 → 四维项 → 镜头，定位主要瓶颈 瓶颈所在的项和镜头
改进 瓶颈项对应到负责环节（T→选题、M→素材、E→讲解、P→生成），只改这一处 具体修改、预期改变的环节、验证方式

原体系区分三种归因，必须分开标明，不能混用：

  • 内容判断归因：为什么认为强或弱，用位置、特征和作用链解释。
  • 预测归因：哪些项相对基线拉高或拉低预估，需要经过验证的预测方法。
  • 修改效果归因：改了这一项，结果是否真的变了，需要 A/B 或前后对照等干预证据。

每条归因结论标证据等级（原体系 A0–A4）：A0 只观察到特征，A1 有作用假设，A2 留存或反馈与假设相符，A3 可比样本重复支持，A4 改变因素后出现预期效果。只有 A3 以上的结论写回钩子库和审片规则，A4 才用于对用户承诺“改这里有用”。不写“选题贡献了 40% 播放量”这类无法支持的数字。

归因结论写回 6.1 的选题预估、6.3 的钩子库和 6.4 的审片规则，形成闭环。

7. 交付承诺与计费

  • 对可测结果负责：留资数、领取数、链接点击与成交（来自 5.1 自持端点），可探索“基础费 + 按结果计费”（按留资数或 GMV 分成）。
  • 对流量负责过程、不保证绝对值：承诺每周复盘、每轮 A/B、留存诊断，不承诺播放量。

8. MVP 顺序

  1. 底座 + 视频专属关键词 + 资料包领取 + 线索表：先建内容基因、结果表、成本表（6.0）；抖音上靠口令归因，允许外链的平台用每视频独立参数的领取页，最快拿出可测结果。
  2. 插件同步后台数据 + 评论区需求挖掘：作品数据、留存曲线、平台组件留资和订单，留存对齐分镜；同一插件读评论区，选题卡加需求证据（6.1）。
  3. 讲解文本层多钩子 + 预评估，评论/私信自动跟进（6.3、6.5）：几乎不增加生成成本。
  4. 审片平台表现维度 + 镜头级重做，结果驱动选题与 A/B（6.4）：截图识别作为兜底。
  5. 三层归因报告写回选题、钩子库、审片规则（6.6）；带货挂载 + 合规审查，以及按结果计费。

每一步的验证：

步骤 验证指标
1 内容基因字段覆盖率；每条视频的口令回复率和领取率；口令归因覆盖多少留资；用户是否愿意把它作为主行动指令
2 插件授权率、同步成功率、留存曲线可读比例；带需求证据的选题卡占比，及其实际表现是否高于无证据选题
3 文本层挑出的开头在 A/B 中胜出比例；自动回复命中率、线索有效率、账号是否触发风控
4 审片预测的掉人点与实际留存曲线下跌点的吻合率；迭代后同账号平均播放和转化是否提升
5 选题预估准确率；带货视频的点击率、成交和合规拦截率

9. 风险与待确认

项 说明 处理
站外导流限制 抖音视频和评论中的外链、二维码可能被限流或删除 抖音只用平台组件和关键词，短链仅用于允许外链的平台
平台接口与资质 平台开放接口的数据与私信能力多需企业资质，各平台开放程度不同（待逐一核实） 先走 5.1 自持端点和 5.2 插件，不阻塞
插件读取后台的边界 涉及用户隐私和平台规则 授权页写明“只读你本人作品的数据”；上线前确认
私信和评论自动化风控 营销私信有频率限制，可能被判定为营销号 限速，关键动作人工确认
广告法 带货有极限词、功效宣称约束 第 5 步加合规审查
结果不可控 流量受平台分发影响 流量只承诺过程；按结果计费设底线和统计口径
定位变化 从“讲解视频工具”走向“知识 IP 增长 Agent”，竞品变成代运营与增长 SaaS 需产品负责人拍板

10. 需要决定的事

  1. 主打线索还是带货（建议线索）。
  2. 是否接受从工具向增长 Agent 的定位转变，并据此修订路线图中“不做发布与数据闭环”的约束。
  3. 插件读取后台数据的授权边界是否可接受。
