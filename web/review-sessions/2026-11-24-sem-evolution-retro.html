一、结论

12 天做了两代引擎加一个重写内核，引擎能力确实变强，但没有证据说明产品路径（DeepSeek 只看题目写稿）的成片质量持续上升。最新两部独立评审是 2.5 和 2.0（满分 5），都判定不能发布。

  1. 每一代换线都没有退出结论。sem 停在 6 题均分 2.92–3.17 外，sem2 停在 30 题首过 83%，都没有写下“哪条假设被证伪、哪些必须带走”。结果是同样的问题（骨架、承接、组件感）换个名字再来一遍。
  2. 优化对象和产品错位。transcribe 两天优化的是“Opus 看着参考片改写”，DeepSeek 写稿几乎用不上新增组件。
  3. 尺子量不到用户要的东西，而且会移动。评委主要看每句静帧，用户抱怨的是换幕、焦点、像 PPT。收敛规则、底线口径、评委、题集都在中途改过，几处头条涨幅来自分母变化。
  4. 内容骨架长期没有固定。引擎每轮都在演一份随机抽到的稿，稿子的波动（同题重写差 0.2–0.6）大于引擎改动。
  5. 增益方向最清楚的是“看过画面再改一轮”，但在 11-21 之后没有作为主线继续。

三、逐段复盘

1. sem（11-13～16）

做了什么：节点 / 关系 / 动作词表、程序修稿、单画布加镜头、占位账本、15 个风格、编辑器与流式分支。

  • 有效：程序修稿与一次列全错误；占位账本 a76333376 把 24 部脚本里持续文字重叠 57 对降到 0 外，但只管文字压文字。
  • 失败：讲法宏，用与不用首稿率 83.5% 对 85.7%，整层删除（66e23101c）外。强制每题一张主图（1bd2adb50），6 题均分 3.17→2.92 外：机制题受益，循环题、尺度题受损。
  • 副作用：单画布改造 924a22a53 换来连贯结构，也带来跳变，用户先发现，评委没发现 外。
  • 缺口很早就定位了：图形数 sem 约 9 对 Opus 37（2026-11-14-sem-eval-system.md），后续没有显著改善；11-15 缺口文档把根子归为全片常驻和身份色，但 27 部里只有 2 部实渲，其余为推断。

3. semk 起步（11-17）

  • 放弃 form 与配方，宽松归一：单个动作错只丢该动作。6 题 × 2 稿 12/12，这与 sem2 的严格首过不能并列。
  • 盲评 6 部：骨架 2.5→3.0，收尾 2.3→3.2，布局和动效都停在 2.7；参考片 5。静止帧占比 0.55–0.68（8c24977a2）。
  • 来回：逐焦点重排每分钟 16–24 次，Opus 为 0 外 → 冻结布局并删自动推镜（43849ff33）→ “像 PPT” → 补回相机（c3fd4645a）→ “运镜有些多” 外。地图插卡 c70caecf9 合入后几分钟即被 e089d9e0f 回退。

教训：运镜、焦点、静止是互相牵制的一组，逐项修会修一面伤一面，需要一次定义“主体稳定、只为内容动”。

三处反复

  • 组件 ↔ 零件：至少 4 轮往返，触发语交替是“像模板 / PPT”和“只有框和箭头、离组件效果差很远”。两句话并不矛盾，共同指向“画面没有题目专属的内容”。
  • 骨架：命名骨架 → 拆掉（3bbe3db8b）→ 内容骨架先行 → 主体 + 状态变化。前两者是版面骨架，后两者是内容骨架，不是同一东西。
  • 承接：同名飞行、整页换掉就退稿、从命名部件长出、兜底交棒、按骨架交棒、关键词胶囊，已试 5–6 种。11-22 复盘的判断是：承接是叙事问题，同名匹配只能做到视觉连着。

11-23 独立评审（pdca126 2.5、fraud56 2.0）：关键数不上屏（12 分钟目标、100 万和 40 万）、高亮指错、重叠与裁切、上一幕残字、末尾总览不可读，另有编造与归类错误（“婚恋借款”、两案合一）。评的是哪个提交（7d79362f8）由会话记录推得 外；没有听音频。

四、分数能信多少

不要把各阶段分数连成一条曲线。题集、评委、次数、量表、稿源都换过：sem 为 Opus 六项看静帧，semk 早期为 codex 适配/讲清楚，transcribe 为“高差距/拍”，loop 为 codex clear，11-23 为独立评审看动态。

  • 噪声：同片重打约 0.17–0.4；同题重写 0.2–0.6。因此盲写 3.17、3.21、3.22、3.21 是同一水平。
  • 可信的方向：与 Opus 的差距长期存在；看画面回改有正收益；DeepSeek 用不上转写组件。
  • 不可信的结论：单轮 ±0.1 的涨跌；“一次通过率”跨引擎比较；程序自报的交棒率；作者模型自评的 3.4–4.3 外。
  • 回归基线放宽过：023276a3c 把 docs/design/semk/regress/baseline.json 中一项 crossed 从 0 改为 3，属于随改动调整基线，理由在提交正文里，但没有单独审过。

五、根因（按影响排序）

  1. 内容骨架没有被固定为独立产物。写稿模型一次同时决定讲什么、画什么、怎么动。11-21 同框架对比：Opus 27 句、set 11 次，DeepSeek 13 句、set 2 次（租房题）。Opus 贯穿一个带数的例子；DeepSeek 写成清单再点亮。旁证只有单例，样本小。反例：换另一版提示时两者持平（wx01 2.85/3.12，opus-revised 页），说明过紧的规则也会把 Opus 压平。
  2. 优化对象错位。环里是看答案的 Opus，产品里是只看题目的 DeepSeek。
  3. 尺子不对齐，也不冻结。静帧打分看不到换幕、焦点、同步，于是“分没动、人说差”长期并存；规则和分母又在运行中改。
  4. 一轮多变量，单片定路线。稿、内核、尺子、样本同时变，看一条新片就换格式。
  5. 通用化与题目专属画面没有分层。强制主图、种类多样、模板组件都把手段当规则；题目专属的图（楔子、聊天记录、20 米路线）始终画不出来。
  6. 软目标做成硬约束。静止、重复、复用限制等直接伤首过，或被改稿绕过。
  7. 换线没有退出门。36 个 sem2 / flex 提交、4 个 sem-hero 提交留在本地，评分材料散在临时目录且已丢，所以旧结论无法复用。
  8. 工具换手后缺独立复验。11-24 三提交由另一工具完成 外，提交说明不足，评审落后一个提交。

八、建议的下一步

只做一条主线，按顺序，每步有停止条件。

  1. 冻结（半天）：备份本机 31 个提交和工作区（推送要你确认）；把 9e19c6ae3 和工作区改动当作未验证的候选，不当新基线。
  2. 定靶（1 天）：选 5 题，跨循环、尺度、因果、对比、案例，调试 2 题 + 验收 3 题，验收题不出现在任何提示和测试里。每题固定 2 份内容骨架（人工或 Opus 定稿）。
  3. 定尺（半天，之后不改）：每次 3 稿均值；同题成对比较；看动态帧带而不是句末静帧；记录关键数上屏率、空屏秒数、高亮指错、残字、裁切。改尺必须重评旧版本。先做同片重评 3 次测噪声，涨幅小于噪声不算。
  4. 分开归因（1 天）：2×2：固定骨架 / DeepSeek 骨架 × 当前引擎 / semk-stable-v1。停止条件：固定骨架仍在 3 以下，问题在引擎；固定骨架明显高、DeepSeek 骨架低，问题在写稿，停止加组件。
  5. 按归因改一处：写稿侧先做“骨架 → 口播 → 一轮看图回改”；引擎侧只修两片评审的共性坏版（残字、裁切、高亮指错、空屏）。
  6. 退出门：两轮验收题均值提升不超过噪声就停下写结论，再决定换路线。

建议固化的四条做法：换线前写一页退出结论；改规则必须重判旧数据；评分原始 JSON 随提交归档到 OSS 索引；提示词、测试里不得出现验收题的数字与名词。

九、没能证实的

  • sem、loop 的绝大多数分数无法从原始数据复算，标 外 的尤其如此。
  • transcribe 的 lift、底线、人选来自其自有页面，人评页默认选中“这一轮”且不盲。
  • 没有做“DeepSeek + 旧内核”对照，因此“新组件没用”不能推到“内核层改动没用”。
  • sem2 与 sem 的同题比较用到不同批次口径，未作为结论。
  • 没有看成片、没有听音频，没有重跑测试。总花费和总耗时没有找到记录。
