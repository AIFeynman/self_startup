1　最小循环：ReAct，和一个我自己写的 40 行版本

起点：没有循环，模型只会说话

模型一次只能输出文字或一个工具调用。要让它「做完一件事」，必须有人把工具结果拿回去再问它。这个「人」就是 loop。ReAct（arXiv 2210.03629，2022）最早把「想一步、做一步、看结果」这个节奏写成范式。二手（本机有深读笔记，本章不重读，当作经典例外之一）

import json, collections

def run(model, tools, task, max_steps=8, window=400, reserve=100, repeat_limit=3):
    msgs = [{"role": "user", "content": task}]
    seen = collections.Counter()
    for step in range(max_steps):
        if size(msgs) > window - reserve:
            msgs = compact(msgs)
        reply = model(msgs)
        msgs.append(reply)
        calls = reply.get("tool_calls", [])
        if not calls:
            return "done", reply["content"], step
        for c in calls:
            if reply.get("stop") == "length":
                out = "ERROR: not executed, output was truncated; re-issue with complete arguments"
            else:
                key = (c["name"], json.dumps(c["args"], sort_keys=True))
                seen[key] += 1
                if seen[key] > repeat_limit:
                    return "stuck", f"{key[0]} repeated {seen[key]} times", step
                out = safe_call(tools, c)
            msgs.append({"role": "tool", "id": c["id"], "content": out[:200]})
    return "max_steps", None, max_steps

def safe_call(tools, c):
    try:
        return str(tools[c["name"]](**c["args"]))
    except Exception as e:
        return f"ERROR: {e}"

def size(msgs):
    return sum(len(json.dumps(m)) for m in msgs) // 4

def compact(msgs):
    keep = msgs[-3:]
    while keep and keep[0]["role"] == "tool":
        keep = msgs[-(len(keep) + 1):]
    note = {"role": "user", "content": f"[summary of {len(msgs)-len(keep)} earlier messages]"}
    return [msgs[0], note] + keep

  1. Pi 的 runLoop 收到一条 stopReason 为 length 的助手消息，里面有两个工具调用。它会怎么做？
    1. 执行第一个，丢掉第二个
    2. 两个都执行，因为参数已经解析好了
    3. 两个都不执行，给每个调用回写一条「被截断，请重新发出」的错误
    4. 直接结束循环
    答案

    C。截断的消息里每个调用的参数都可能残缺，所以整批判失败（failToolCallsFromTruncatedMessage）。一手

  2. Codex 里，一个工具没有声明支持并行。它执行时会发生什么？
    1. 拿读锁，和别人一起跑
    2. 拿写锁，期间其他工具调用都进不来
    3. 被丢到另一个线程池
    4. 直接报错
    答案

    B。supports_parallel 为真拿读锁，否则拿写锁（parallel.rs 第 330 行起）。一手

  3. 论文 2610.29869 里，为什么 Codex 等「带角色型」harness 对压缩洗白攻击免疫，而 pi 等拍平型不免疫？
    1. 前者用了更强的模型
    2. 前者的摘要提示词里写了防注入规则
    3. 前者保持消息带角色，工具输出始终是工具角色，没有可伪造的文本标签
    4. 前者不做压缩
    答案

    C。差别在序列化方式，不在模型或提示词；提示词里的防注入规则只挡 13–25%。一手（论文）

    1. 22% 的任务解不出来
    2. 有些 run 已经产生通过测试的补丁，却因为没按时收尾被取消，「做对了」和「自己停下来」是两个终点
    3. 评测的测试用例有 22 个写错了
    4. 中立 harness 比原生 harness 少 22% 成本
    答案

    B。建议同时报告解题率、终止状态分布和完成时间。一手
