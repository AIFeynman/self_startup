1　为什么窗口越满越不准

起点基线：以为「窗口开到 1M 就不用管了」

不管的后果：成本按轮次累积，且质量下降。Chroma 的 context rot 报告测了 18 个模型，结论是输入变长后表现普遍变差。二手（我只见到转述，没读到原报告）

新的解释：问题在「注意力被抢」，不只在「长」

2611.04169 做了一个很干净的对照：往窗口里塞中性填充文字，准确率几乎不掉（0.97–1.00）；塞和证据格式相似的干扰内容，准确率掉到 0.16–0.33。论文还报告：证据上的注意力占比能解释最多 58% 的损失方差，而 log 长度只能解释最多 8%。二手（读研究笔记，未读原文；且只测了小模型，大模型是否同样要自己验证）

设计原理：这对工程意味着什么 判断

  • 「删掉没用的」比「压成更短」更对症：目标是减少和证据长得像的干扰，而不是单纯缩字数。
  • 同类东西别堆在一起：十次相似的 grep 输出，比十段不相干的日志更伤。
  • 这是小模型实验。别把 58% 当成通用常数用。

2　裁剪（pruning）：在工具输出进窗口前就删行

这一节补 C1 §7 没覆盖的部分。C1 讲的是「历史已经在窗口里，怎么压」；这里讲「新来的工具输出，要不要全放进去」。判断 数据：file-reading 命令在 Mini-SWE-Agent + Claude Sonnet 4.5 的 SWE-Bench Verified 轨迹里占了超过 70% 的 token（SWE-Pruner Pro 论文 §2）。一手

Agent 读一个 2000 行的文件，只需要其中 30 行。剩下 1970 行留在窗口里，每一轮都被重新处理，直到被压缩。这是最常见也最贵的浪费。判断

拆解二：Squeez 和 SWE-Pruner Pro

  • Squeez：只做一件事，「给一段工具输出和一句查询，返回该保留的行」。2B 的微调模型比没微调的 Qwen 3.5 35B A3B 零样本 recall 高 11 个点，比没微调的 2B 基座高 33 个点。一手 教训：专用小模型 + 微调，比大模型零样本更会「抽行」。
  • SWE-Pruner Pro：不另训分类器骨干，直接读 Agent 自己模型的最后一层隐状态，接一个小头做逐行保留判断，并加一个「行数 N」的长度嵌入（短输出里误删几行比长输出里代价大得多）。作者先用线性探针证明隐状态里已经有「该不该留」的信号，但两类分布重叠明显。一手

坑 1：裁剪是不可逆的，除非你留了原文。把原文存到文件里，窗口里只放裁剪结果加一个「原文在哪」的指针。Manus 的做法就是这样「可恢复的压缩」。二手

坑 2：目标提示写偏，整个裁剪就偏。SWE-Pruner 靠 Agent 写的 context_focus_questions 决定留什么（附录的提示词里有这个字段）。一手 Agent 一开始就不知道要找什么时，这一步最容易删错。判断

坑 3：Squeez 说「常丢掉看起来像样板的行，其实有用」。（论文结果部分的错误分析）一手 日志里的 WARNING 行、重复的 import 行，看着没用，偏偏是答案。

框架里怎么实现（三）：Graphiti 不删，只标「失效」

文件：getzep/graphiti，graphiti_core/utils/maintenance/edge_operations.py，分支 main，读取日期 2026-11-16。一手

def _apply_temporal_invalidation(resolved_edge, invalidation_candidates):
    """Expire the resolved edge and any candidate it contradicts. ..."""
    now = utc_now()
    # The edge arrived with an end date, so it is already historical.
    if resolved_edge.invalid_at and not resolved_edge.expired_at:
        resolved_edge.expired_at = now
    # A candidate that starts later supersedes this edge, so expire this one instead.
    if resolved_edge.expired_at is None:
        invalidation_candidates.sort(key=lambda c: (c.valid_at is None, ensure_utc(c.valid_at)))
        for candidate in invalidation_candidates:
            if (candidate_valid_at_utc > resolved_edge_valid_at_utc):
                resolved_edge.invalid_at = candidate.valid_at
                resolved_edge.expired_at = now
                break
    return resolve_edge_contradictions(resolved_edge, invalidation_candidates)

（中间的变量赋值我略掉了；条件和赋值语句与原文一致。）调用链：resolve_extracted_edges 去重 → _apply_temporal_invalidation → resolve_edge_contradictions → 被矛盾的旧边得到 invalid_at / expired_at。一手

  • 旧边不删，所以可审计、可回溯；代价是图只增不减。

Anthropic 原文：记忆是对「未来要用什么」的预测，加上 dreaming

缓存纪律：为什么「省 token」和「省钱」会冲突

Prompt cache 只认前缀。只要在前面改一个字，后面全部重算。所以：二手（Codex 博客，C1 §7 已讲机理）

做法对缓存的影响适用
只追加（append-only）前缀不变，命中默认

精读 2　MemGPT（arXiv 2310.08560）：DMR 的 93.4% 是怎么来的

一句话：上下文装不下时，让 LLM 自己当操作系统，把数据在「内存」和「磁盘」之间搬。答：能，而且在它自己造的两个测试上很强。一手

方法：

层内容谁管
主上下文（相当于内存）系统指令、工作上下文（可写）、FIFO 队列（含最前面一条递归摘要）LLM 通过函数调用读写
外部存储（相当于磁盘）回溯存储（全部历史）、归档存储（任意文本）LLM 用分页检索调进主上下文
