# 主题学习计划：方法论与 JSON 格式

目标：把一个陌生主题变成循序渐进的学习路径。三轮由浅入深，每步都可打分、反馈、调整。不同领域学法不同：每轮学什么、主材料是什么、怎么考，都按本计划的学法来。

## 三轮（stage 字段填 1 / 2 / 3，按顺序；每轮结束用户都可以停下）

主线只讲主干，用户对某个点感兴趣或没懂时，平台会「按需加一节」现场补，计划里不要预先铺满。

总共 8–11 步，主线总时长 15–20 小时（每周投入多的可以到 25 小时，少的压到 12 小时），每步不超过 2 小时（实践步骤不超过 3 小时）。按用户背景跳过已会内容、加强薄弱处。

每一步之后会被平台展开成一章教程 + 章末测试，所以步骤要「一章能讲完、能考」：主题聚焦，`goal` 写清这一步学完要具备的具体能力，必须可检验。

## 资源要求
- 只给真实存在的链接；能访问的先用 WebFetch/curl 核对，`verified: true`；无法核对的 `verified: false`，不要编造 URL。
- `type`: paper / book / course / video / blog / repo / doc / talk / product。
- 有日期的资料写 `date`（发表 / 更新日期）；产品写清是否免费、怎么开始用；其他要求见学法。
- `why`: 一句话说明它在这一步解决什么。

## 检查题
- 每步 2–4 道，能检验理解和判断而非记忆。

## 生成计划时输出的 JSON（最终回复里放一个 ```json 代码块）
```json
{
  "method": "tech | design | business",
  "overview_md": "Markdown：第一行写「学法：<名字> —— 为什么选这套」；然后主题边界、底层逻辑一段话、路线总览（每轮一句话写清目的）、资料时效（主要资料的日期、是否最新）、资料核对日期",
  "steps": [
    {"stage": 1, "title": "...", "goal": "学完这一步能做到什么（具体、可检验）", "description": "做什么、产出什么（Markdown 可）",
     "resources": [{"title": "...", "url": "https://...", "type": "paper", "date": "2026-08", "why": "...", "verified": true}],
     "questions": ["..."], "est_hours": 3}
  ]
}
```

## 根据反馈调整时输出的 JSON
```json
{
  "summary": "一两句：发现了什么问题、怎么调",
  "edits": [
    {"op": "add", "stage": 2, "after_step_id": 12, "title": "...", "description": "...", "resources": [], "questions": [], "est_hours": 2},
    {"op": "modify", "step_id": 13, "title": "...", "goal": "...", "description": "...", "est_hours": 3, "questions": ["..."]},
    {"op": "skip", "step_id": 15, "reason": "已掌握"},
    {"op": "add_resources", "step_id": 12, "resources": [{"title": "...", "url": "...", "type": "blog", "why": "补救：..."}]}
  ]
}
```
调整原则：章末测试得分低（<60）或理解度 ≤2 或反馈说没懂 → 补前置/换更易懂的资源（add_resources 或 add 补救步）；理解度 5 且很快完成 → 后续同类步骤可 skip 或加深；不修改已 done 的步骤；只做有依据的少量修改。

## 老计划（六阶段）

2026-10-31 之前生成的计划用六个阶段：1 领域综述、2 核心人物与观点、3 关键书籍 / 经典论文、4 核心机制 / 概念精学、5 前沿进展、6 实践与输出。调整这类计划时 stage 仍按六阶段填（任务里会写明计划用哪种结构）；用户想换成三轮时，平台会另生成一份三轮计划，旧计划保留。
