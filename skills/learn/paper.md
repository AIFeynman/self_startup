# 论文深读：在 paper-library 格式上的增补

基础流程与证据要求以 `~/.codex/skills/paper-library/SKILL.md` 及其 `references/deep-reading.md` 为准（读全文、机制链、证据边界、原文定位、区分作者结论/代理推断）。本平台的差异与增补：

## 产物位置
- 只写到任务给出的输出目录：`note.md`（主笔记），关键图放 `figs/`（按任务里的「关键图」规则下载、查看、在正文对应位置嵌入并配说明）。PDF 等附件也放该目录。
- 除非任务明确说「允许写入 Obsidian」，不要写入 paper-library `config.json` 里的知识库，也不要修改该 config。
- 主笔记可沿用 paper-library 的 frontmatter 和「动机 / 关键结论 / 认知更新 / 最小机制与证据 / 论文关系」结构，但顶部和末尾按下列增补。

## 增补段落（按顺序）
1. **TL;DR（文件最开头，正好 3 行）**：`## TL;DR` 下三条 `- `：①它解决什么问题、核心做法；②最有说服力的证据（带指标与条件）；③最大的局限或最容易误解之处。
2. **与我已有知识的联系**：最多 2 条，按任务说明里「联系与启发」的要求写。
3. **可迁移结论 / 对我的启发**：1–2 条，按任务说明里「联系与启发」的要求写；标注这是代理推断。
4. **追问清单**：3 个最值得继续追问的问题，按「理解机制 → 质疑证据 → 迁移应用」排序，每个问题一行、能直接复制到对话里问；检验理解的练习题另写在 qa.json（选择题为主，见任务说明）。
5. **最小上手实验**（放在追问清单之前）：一个 30–90 分钟能做完的小实验，用来亲手验证论文的核心机制，而不是复现全文。写明：①要验证的那条结论；②最小设置（模型/数据/脚本，优先作者开源代码或纯 prompt 方案）；③3–6 步操作；④预期观察和「看到什么算机制不成立」。只写步骤，不要实际运行；论文没有可行的小规模验证时写明原因，并改为一个读后练习（例如用自己的任务套一遍方法）。

## 风格
- 中文解释，保留英文术语、公式和标题；一屏到两屏可读，深度体现在因果与证据，不在篇幅。
- 未读到全文时写明 `reading_status`，不要假装 deep。
