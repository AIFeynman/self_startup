# GitHub 项目解读：在 github-code-walkthrough 格式上的增补

基础流程以 `~/.codex/skills/github-code-walkthrough/SKILL.md` 及其 `references/` 为准（固定 commit、从真实入口追调用、整体流程图主导航、函数级讲解、离线单文件 HTML、`scripts/check_html.py` 检查）。本平台的差异与增补：

## 产物位置
- 源码 clone 到输出目录下的 `src/`（`git clone --depth 1`，不执行安装脚本）。
- 教程写 `index.html`（离线、无 CDN）；生成器/布局 JSON 可放同目录。README / docs 里的架构图、效果图下载到 `figs/`，在 HTML 和 summary.md 里用相对路径 `figs/…` 引用。
- 另写一份 `summary.md`（给对话 Agent 和列表用，短小），结构：
  - `## TL;DR`：正好 3 条 `- `：①项目做什么、给谁用；②核心架构一句话（入口 → 核心机制 → 产物）；③最值得学的设计/最大的坑。
  - `## 与我已有知识的联系`、`## 可迁移结论`、`## 最小上手实验`、`## 追问清单`（同下）。
  - 末尾 `## 我的笔记`（空）。

## 文档与例子精读（必做，不能只读代码）
- 解读前先列出仓库里的文档和例子：`docs/`、`doc/`、`examples/`、`example*/`、`samples/`、`cookbook*`、`SETUP.md` / `CONTRIBUTING.md`、仓库内的 `skills/*/SKILL.md`、`prompts/`，以及专门检查文档的测试（如 `tests/docs.spec.ts`）。
- **逐篇通读**，不能只扫标题。体量很大时（> 5000 行）按 README 给的阅读顺序读核心篇目，其余至少读目录和每篇开头，并在「覆盖范围与限制」里写明哪些没读全。
- HTML 加一节 **「文档与例子精读」**（放在函数讲解 / Prompt 之后、「与我已有知识的联系」之前，并加进目录），包括：
  1. 阅读顺序，以及文档之间的依赖关系；如果有测试守着文档（链接、索引和代码要一致），要说明。
  2. 逐篇卡片：一句话定位、3–5 条要点、与代码的对应（文件/函数）和我的判断。文档和代码不一致时要点名。
  3. 例子表：每个例子是什么、演示了哪条机制或契约、怎么用；可运行的例子标明是否实际跑过。
  4. 「文档对前文解读的补充与修正」：文档回答了哪些追问、纠正了哪些推断、承认了哪些未决问题或限制。
  5. 从文档写法本身学到的东西（比如拒绝方案表、阅读顺序约束），可选。
- 文档里的关键数字和断言（超时、阈值、重试次数、权限边界）至少抽查 3 处是否与代码一致，并写明结果。
- `summary.md` 里加 `## 文档与例子要点`（3–5 条）。
- 仓库本身就是文档或书时，按上面的「阅读指南」处理，本节合并进去。

## HTML 中增补的章节
1. **页首 TL;DR**：同上 3 行，放在流程图之前。
2. **与我已有知识的联系**：对照任务给出的用户已学条目，说明具体关系；没有就写暂无。
3. **可迁移结论 / 对我的启发**：2–4 条可以带走的工程/算法设计经验，注明边界。
4. **最小上手实验**：一个 15–30 分钟能跑通、能观察到核心机制的实验：前置条件、命令（3–8 步）、预期观察、改一个参数看变化。标明是否实际运行过；不要为此安装重依赖、调用付费 API。
5. **追问清单**：5–8 个问题，按「架构 → 关键函数细节 → 改造/迁移」排序，可直接复制到对话。
