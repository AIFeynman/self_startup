## 学法：技术研究

学成 = 能推导、能实现、能判断论文。三轮计划的全貌、前沿章节和老计划阶段 1、3、5 必有 `## 资料时效`。正文小节区分「源文事实」和「解读者判断」，讲到机制时具体到推导、数字和代码。

老计划阶段 2 和三轮的人物章，测试至少 1 题给真实的新事件，参考答案写出代表人物会怎么看。

## 每一轮的目的（三轮计划；决定这一章写什么、考什么）

任务里会写本章属于第几轮、这一步是哪一类（看标题和说明判断）。

| 轮 / 类型 | 目的（学完要能做到） | 章节必须覆盖 | 测试重点 |
|---|---|---|---|
| 1 · 全貌 | 拿到**最新**的领域地图，能把任意新论文 / 新产品定位上去 | 先核对主读物的日期：联网确认它是不是近 12 个月最新、最好的综述或书，不是就换或补；**体系架构图（必有，见下）**；分类树；方向 ×{核心问题、痛点、主流方案、热点、开放问题}矩阵；最近一年地图上变了什么 | 定位题、「为什么这个问题还没解决」 |
| 1 · 主干机制 | 吃透撑起地图的核心机制 | 直觉 → 形式化（推导一步步来）→ 最小实现 → 常见误解 → 失效边界 | 推导 / 找错 / 改条件后的结果预测 |
| 2 · 经典讲透机制 | 知道主干怎么来的、为什么有效 | 当时卡在哪 → 一句话关键洞察 → 方法核心 → 证据 → 局限 → 后续谁接着做；只讲第 1 轮没讲过的深度，不重复 | 「去掉 X 会怎样」、把思想迁移到新问题 |
| 2 · 人物与判断 | 像一线的人一样判断 | 同下表阶段 2 | 同下表阶段 2 |
| 3 · 前沿 | 快速消化新论文并判断价值 | 只用**最新**材料（近 6–12 个月，优先 3 个月内），联网核对；每篇写日期和证据级别、相对已有工作的增量、可疑之处；最后「现在前沿在哪、下一步可能是什么」 | 增量识别、证据可信度、趋势判断 |
| 3 · 项目实践 | 看懂开源项目怎么把机制落成代码 | 仓库概况（star、最近提交、活跃度）→ 架构一条主链路（入口 → 核心模块 → 产物，关键文件带链接）→ 本领域的哪个机制在哪段代码里、做了什么工程取舍 → 最值得读的 3–5 个文件 → 一个动手小练习（clone 后跑什么、改什么、观察什么） | 「这段设计为什么这样取舍」「换成 Y 场景要改哪里」 |
| 3 · 产品实践 | 亲手用对标产品 / 工具，写出有依据的使用评估 | 每个产品：是什么、怎么开始用（是否免费、注册入口）→ **上手任务清单**（3–5 个具体任务，覆盖本领域的核心能力和已知难点）→ 评估维度（4–6 条 rubric：能力、效果与证据、和本领域方法的对应、短板与坑、适合谁、和同类比）→ 你（作者）检索到的公开评价和已知问题，标注来源和日期 → 一张对比表留空让用户填 | 测试里至少 1 道 short 让用户**按评估维度写自己的使用评估**（rubric 就是评估维度，看是否有亲手用过的证据和判断，不看文笔） |

## 老计划的六个阶段（决定这一章写什么、考什么）

| 阶段 | 目的（学完要能做到） | 章节必须覆盖 | 测试重点 |
|---|---|---|---|
| 1 领域综述 | 对领域有**整体地图**：分类体系、每个方向的痛点 / 热点 / 开放问题 / 主流方案，能把任意一篇新论文或新产品定位到地图上 | 资料时效评估；分类树；方向 × {核心问题、痛点、主流方案、热点、开放问题} 矩阵；方向之间的关系与演进；底层约束 | 定位题（给一篇新论文/新产品，归到哪个方向、解决哪个痛点）、对比题、「为什么这个问题还没解决」 |
| 2 核心人物与观点 | **提升判断力**：知道一线人物怎么看问题、依据是什么、哪些判断后来被验证或被推翻，能对新事件做出同等深度的判断 | 每人：核心判断 → 依据与推理链 → 过往预测与后来的实际情况 → 与他人的分歧点；一张「分歧地图」；一个新近事件让各人「隔空点评」 | 判断题（给一个新事件/新论文，X 会怎么看？你怎么看？依据是什么）、识别论证漏洞、预测题 |
| 3 经典书籍/论文 | **快速吸收核心思想和背后逻辑**：10 分钟内能讲清一篇经典的问题、关键洞察和为什么有效 | 每篇：当时卡在哪 → 一句话关键洞察 → 方法核心（最少的公式/图）→ 证据 → 局限 → 它改变了什么、后续谁接着做；「读哪几节」的导读 | 一句话核心思想、「如果去掉 X 会怎样」、把思想迁移到新问题 |
| 4 核心机制/概念 | **吃透机制**：能推导、能自己实现最小版本、知道失效条件 | 直觉 → 形式化（推导一步步来）→ 最小实现（伪代码/短代码）→ 常见误解 → 失效边界 | 推导/计算题、找错题、改条件后的结果预测 |
| 5 前沿进展 | **快速消化新论文并判断价值**：知道相对经典增量在哪、证据是否可信、代表什么趋势 | 每篇（写日期、证据级别：预印本/会议/已部署）：相对已有工作的增量、关键证据、可疑之处、对趋势的意义；最后综合「现在的前沿在哪、下一步可能是什么」 | 增量识别、证据可信度判断、趋势判断 |
| 6 实践与输出 | **用产出检验理解** | 项目说明：目标、验收标准（rubric）、分步路线、常见坑、自检清单 | 用 rubric 自评题 + 设计取舍题 |

## 首章：体系架构图

计划的第一步（全貌章，任务里会注明）：`## 体系架构图` 紧接在资料时效后面，必须用下面的组件画出这个领域的分层架构，图下用 3–6 句讲清各层之间怎么依赖、信息 / 数据怎么流动、当前热点和瓶颈落在哪一层；之后再接全景图（分类树、矩阵）。

**体系架构图**（领域的分层结构；计划第一步必画，其他章节讲系统组成时也可用）：从上到下 3–5 层（上层是应用 / 产品 / 场景，往下是方法 / 系统、核心机制、基础与数据 / 算力 / 理论，按领域实际取舍），每层 2–6 个模块；右侧可选一列「贯穿各层」的横切关注点（评测、安全、成本、工具链等）。模块里可以放 `dg-more` 点开看细节（代表工作、为什么在这一层）。
   **点击跳转**：模块对应计划里的某一步时加 `data-step="<step_id>"`（任务里会列出各步的 step_id），对应本章某个小节时加 `data-section="<小节标题>"`；都不对应就不加，平台会在模块上放「展开讲」，用户点了就按需生成一节讲它。
