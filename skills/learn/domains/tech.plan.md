## 学法：技术研究（method: tech）

适用：Agent 评测、语言模型、Benchmark 这类技术方向。学成 = 能推导、能实现、能判断论文。主材料是综述、论文、仓库。

技术发展很快，所以**先给最新的全貌，再往深处走**。

1. **第 1 轮 · 看懂：最新全貌 + 主干机制**（2–3 步，约 5 小时）
   - 目的：拿到这个领域**最新的整体地图**（分类、每个方向的痛点 / 热点 / 开放问题 / 主流方案），并吃透撑起它的 2–3 个最核心机制；学完能把任意一篇新论文或新产品定位到地图上、讲清它靠什么机制工作。
   - 第一步的章节会画出这个领域的**体系架构图**（分层 + 贯穿各层的关注点，模块可点击跳到计划里讲它的那一步），所以第一步的 goal 写「能画出 / 讲清这个领域的体系架构，并把新论文定位到具体层和模块」，后面各步最好能对应到架构图上的模块。
   - 第一步必须基于**最新的综述或书籍**：先联网检索近 12 个月的综述 / 书 / 权威课程（arXiv、出版社、作者主页），选最新且质量高的作为主读物，写明发表或更新日期；最新的也超过 12 个月时，在步骤里说明之后的关键变化、补读什么。不要用三年前的经典综述当全貌。思路可参考 `~/.codex/skills/domain-landscape/SKILL.md`（根问题、约束、核心机制、失效边界、相邻领域）。
   - 机制步骤：每步一个机制，直觉 → 形式化 → 最小实现 → 失效条件，附可推导 / 可复现的材料。
2. **第 2 轮 · 会判断：经典讲透机制 + 一线人物的判断**（3–4 步，约 6–8 小时）
   - 目的：知道主干是怎么来的、为什么有效，并能像一线的人一样对新方案下判断。
   - 经典论文和机制合在一起讲：「一篇奠基论文讲透一个机制」——当时卡在哪 → 关键洞察 → 方法核心 → 证据 → 局限 → 后续谁接着做。不要把经典和机制拆成两步重复讲。
   - 人物观点放在这一轮（懂了机制才看得出判断的好坏）：3–6 位代表人物 / 团队，「核心判断 → 依据 → 过往预测与后来的实际情况 → 分歧」。
3. **第 3 轮 · 跟前沿、做出来：最新进展 + 项目与产品实践**（3–4 步，约 6–8 小时）
   - **前沿**（1–2 步）：同样要**最新**——近 6–12 个月的论文、技术报告、开源发布，优先最近 3 个月；每项写日期和证据级别（预印本 / 会议 / 已部署）、相对已有工作的增量、证据可不可信。
   - **项目实践**（1 步）：挑 1–2 个代表性的 GitHub 开源项目（写 star 数和最近提交日期，选活跃的），读架构和关键实现：它把本领域哪个机制落成了代码、做了哪些工程取舍；资源里放仓库链接（type: repo），平台可以一键速读。
   - **产品实践**（1 步）：挑 1–3 个对标的外部产品 / 工具 / 服务（真实存在、用户能上手的，写清是否免费、怎么开始用），让用户**亲手用**，按评估维度写一份使用评估：能做什么、效果和证据、和本领域方法的对应、短板与坑、适合谁、和同类比怎样。评估维度在步骤 description 里给出（4–6 条，可直接当 rubric）。

资源要求：综述、书、前沿论文写 `date`；仓库写最近提交日期和 star 数。检查题问「为什么」「如果没有…会怎样」「如何验证」。`goal` 例：「能把一篇新的 Agent 评测论文归到 4 个分支之一并说出它针对的痛点」「能按 5 条维度写出对 X 的使用评估并和 Y 对比」。
