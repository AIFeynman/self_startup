## 学法：商业与增长

学成 = 面对真实局面能做决策，并说清依据和代价。和通用结构冲突时听这里。不写技术架构和实现原理，只有影响决策时才提一句。

| 轮 | 章节写什么 | 测试重点 |
|---|---|---|
| 1 看局面 | 真实案例：当时的局面、选了什么、数字结果、账怎么算 | 算账、归类打法 |
| 2 会判断 | 操盘人的分歧，事后验证了什么；什么条件下结论会翻 | 决策情景、识别不可复制的成功 |
| 3 做一次 | 实验设计：假设、指标、成本、停止条件；回来怎么复盘 | 写实验方案、复盘真实数字 |

### 章节结构

1. 开头引用块照旧。接着 `## 你来决定`：给一个真实局面和数字，一张 `dg-flash` 让用户先做决定、写依据和代价。这时不讲框架。
2. `## 资料时效`（必有）：数字的日期，之后市场或平台规则有没有变。
3. 每个案例一节，都写：当时的局面、选择和放弃了什么、数字结果、账怎么算（用 markdown 表格一步步算）、能不能复制。节末「停一下」问用户的决策。
4. 框架在案例之后才出现。通用结构的 `## 一条主线走一遍` 写成一个决策从局面走到结果；`## 我的判断框架` 写成决策清单。
5. 每个数字写来源和日期，自己的估算标 `<span class="judge">解读者判断</span>` 并写出假设；查不到写「未公开」，不要编造。

### 测试

- 题型：决策情景、算账、复盘。算账题给齐数字，`choice` 的答案要能算出来。
- 决策题不判唯一答案：`reference` 写操盘人公开的做法（带出处）作对照，`rubric` 看依据是否来自数字和案例、是否说清代价、什么情况下会改主意。

### 首章：案例地图

计划第一步写 `## 案例地图`：按打法分组摆代表公司（`dg-cards` 或 markdown 表格），每家写打法、关键数字和日期、结果，写明后面哪一章会细讲它。
