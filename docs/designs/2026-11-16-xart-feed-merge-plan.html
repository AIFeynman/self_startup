X 长文与重点作者方案

整体合并版：长文库、信息推荐的 X 长文、重点作者抓取与提炼，共用一套每日增量抓取和一个月度预算。只出方案，没有改代码。

结论

三件事并成一条每日流水线，每天都抓，靠「已见过就不再取」避免重复花钱。长文库是长文的唯一来源，信息推荐的「X 长文」标签改读它；重点作者另建推文库，做相关判断、打分和提炼。月度预算上限 100 美元，计划用约 60 美元，月累计到 90 美元自动停。

每天都抓，不重复抓

每日定时→长文搜索：昨天+今天→已见过的 id 只更新阅读数→新 id 过门槛才取全文→重点作者时间线（只取比上次新的）→判相关 / 打分提炼→同步知识库
  • 不重复的做法：所有 id 按表主键去重；取全文前先查库，已有全文的跳过；作者时间线记每人「上次抓到的最新推文 id」，下次只要更新的；同一天跑两次，第二次不产生取全文和打分的花费。
  • 当天就抓：搜索窗口取「昨天+今天」。今天刚发的长文阅读数还低，会被门槛挡下，但行保留；第二天窗口再扫到时更新阅读数，过线就补取全文。这样既当天可见，又不漏。
  • 名单作者和大号：不受阅读门槛限制，发了就取。

重点作者：扩充和提炼

做法
现状信息推荐里关注名单 96 个账号，每人最多取 2 条，互动数≥100，只做排序，不提炼。
扩充从长文库里找候选：质量分≥4 的长文作者，出现 2 篇以上的，列成「建议加入」清单，你一键确认才入名单（名单是你的口味，不自动加）。名单目标 150 到 200 人。
抓取每人每天 1 次时间线调用（约 20 条），取比上次更新的推文。名单 200 人约 0.2 美元/天。
提炼本机 haiku 免费：先判是否 AI 相关，再对相关的串推和长推打分，提炼一句要点和可迁移的点；每个作者每周生成一条「作者动态」进知识库，新类型 xauthor，同样可检索。
和长文的关系作者发的长文走长文库的全文和打分，不在推文库里重复提炼；推文库只放非长文推文，引用长文的推文把长文 id 交给长文库。

风险和回退

  • 定时任务停了，两个标签都会不更新。缓解：失败提醒，标签页顶部显示最近一次抓取时间。
  • 作者时间线的接口花费和返回条数我还没实测，上线第一天先只跑 20 个账号，核对后再放开。
  • 质量分口径还没按你的留/弃结果校准，标签阈值先放 ≥2。
  • 回退：旧逻辑在 git 历史里，一个提交可还原；预算常量集中在一处。
