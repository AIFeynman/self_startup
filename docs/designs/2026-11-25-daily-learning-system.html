3. 设计原则

  1. 从你的问题出发：深度主题、动手选品、回忆题，优先来自你自己问过还没解决的问题。
  2. 复用优先：能用现成的卡、章节、深读，就不重新生成。
  3. 补短板：每天至少一道“给场景、做决定、说怎么验证”的应用题。
  4. 一个入口，有上限，看完即止：每天 3 张精读 + 约 5 张速览，张数按数据调，不凑数。
  5. 先结论，固定版式：30 秒能决定要不要往下看。
  6. 宁缺毋滥：没有合格内容就空着，生成失败的内容不进新 TAB。
  7. 质量要能计分：每个目标对应一个每周能算的数。
  8. 量力而行：大模型任务有每日预算，按优先级排队。

9. 新 TAB：现有栏目一律不改，只读复用

原则：现有栏目、TAB、页面和数据流一律不动。新做一个独立板块（暂名“今日”，名字待你定），把这份设计里所有新东西都放进去：它从现有栏目只读取内容，需要记录的东西存在它自己的表里，或者通过现有接口写进判断台账、产品体验等原有功能。平台的板块是自动发现的，新增一个板块不需要改其他栏目的代码。

12. 内容质量门和产能预算

质量门

  • 把增长 Case 的标准推广到所有卡：每条事实带来源和日期；自述数字和核实数字分开；推测标出来；写利益关系；没读到的写“未读到”。
  • 生成失败的不进新 TAB（读取时过滤，不改原栏目）：检查章节是否齐全、长度是否够、有没有报错或 Agent 闲聊。现状：产品雷达 332 张卡里有 10 张是垃圾（一张是 Agent 解释它没改某个配置文件，一张是“已达到周额度”报错），另有 25 张不完整。
  • 宁缺毋滥：槽位没有合格内容就空着。
  • 按你的反馈自动调配额：卡上一键“没增量”；某类卡有增量的比例低于 50% 就减配额。
  • 人抽检：周成绩单附 3 张被拒的卡，你只看拒得对不对。
