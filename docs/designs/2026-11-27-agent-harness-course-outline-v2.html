Agent Harness 实践课提纲 v2

主线：DeepSeek Harness（dsh），官方 Python SDK 在课程页面里逐格驱动。2026-11-27

本版变更（相对 v1）
  • 主线确定为 dsh。其他项目里有价值的机制（记忆、Hooks、交接文件、workflow 续跑等）都改成在 dsh 上实现，不再只是「去看另一个仓库」。
  • 新增第二部分「让 harness 自己变好」（第 12–16 课）：尺子、信号与归因、写回 7 层、进化外循环、闸门与运行中自进化。这些是 dsh 没设计的环节，在 dsh 上用 Python 搭出来。框架沿用平台已有的《Harness 自进化 Know-how 地图》（2026-11-22）：被进化的 7 层对象、7 步闭环、L0–L4 成熟度。
  • 扩展方式改为「Python 优先」：dsh 能接本地 stdio MCP 服务、能通过 hooks 桥运行任意命令钩子，所以新能力用 Python MCP 服务、确定性约束用 Python 钩子脚本、配置用 patch 文件。写 TypeScript 原生插件降为可选，不装 Node 也能学完。

课程怎么搭

两部分，前一部分给后一部分准备好零件：

  1. 拆 dsh（第 0–11 课）：逐个环节看 dsh 怎么做、改它、量出差别。dsh 没有的环节（长期记忆、确定性钩子、会话交接）在这一部分用 Python 补到 dsh 上。
  2. 让 harness 自己变好（第 12–16 课）：用前面得到的轨迹、反馈和可改的层，搭一个「采信号 → 归因 → 提议 → 验证 → 晋升 → 写回」的闭环，最后让 dsh 自己改自己的配置，并检验改进是真的还是刷分。

每课骨架：根本问题 → dsh 怎么做（源码位置）→ 动手（可量化的现象）→ 对照材料 → 坑。课程自带一个小工作区（带测试和种子 bug）和一组可自动判分的小任务，后面的评测和进化都用它。

第一部分 · 拆 dsh

0 开课：模型 + harness，各管什么

20 分钟profile：sdk-minimal vs sdk
动手
装 SDK，隔离 DSH_HOME；同一个修 bug 任务分别用 sdk-minimal（只有 shell + 压缩）和完整 sdk 跑，比工具清单、步数、token、测试是否通过；打印两个 profile 的配置树，标出多出来的包。
对照
learn-claude-code「Agent = 模型 + Harness」；Know-how 地图 A1「同一模型换外壳分差十几到二十分」。

1 循环：一轮里到底发生了什么

30 分钟core/agent-loop
dsh 怎么做
agent.ts：请求 → 流式解析 → 工具执行 → 结果回填 → 再请求；inbox.ts：运行中插入的消息如何进循环。
动手
订阅通知画轨迹（每步：请求、工具、耗时、token、缓存命中）；给一个做不完的任务看 finish_reason；运行中 steer 一句话看从哪步生效。
对照
learn-claude-code s01 的 30 行循环，逐项对到 dsh 轨迹上。

2 工具：模型看到的，和真正执行的

35 分钟core/tools · tool-executor-native / ptc
动手
同一多文件检索任务用 native 与 PTC（Code mode）执行器各跑一次，比请求数、token、耗时；patch 关掉文件工具看模型怎么绕；让工具报错看恢复。
对照
learn-claude-code s02；dsh-handbook 第 8 章。

3 上下文与缓存：每次喂了什么、花了多少

35 分钟context · system-prompt · llm
动手
把一次请求按来源拆成堆叠柱（系统提示 / 工具定义 / AGENTS.md / 历史 / 本轮）；连跑 5 轮记录缓存命中与费用，再在前缀插时间戳对比；改 AGENTS.md 一条规则看是否被遵守。
对照
dsh-handbook 第 14 章（命中率 97% 的条件）；learn-harness-engineering 第 4 讲；Know-how 地图 F1「常驻上下文怎么限量」。

4 上下文满了：大输出转存与压缩

40 分钟spill · compaction-basic · tool-result-pruner
动手
工具吐 200KB 日志看 spill 后模型拿到什么、能否取回；长会话触发自动压缩，压缩前后各检查一次早期约束（如「不许改 tests/」）的遵守率；patch 换压缩策略再比。
对照
learn-claude-code s08 四步压缩；论文 Governance Decay（2026，压缩会抹掉安全约束）。

5 长期记忆：dsh 没有，自己接一个

40 分钟补到 dsh 上Python stdio MCP + skill
根本问题
会话一结束经验就没了。记什么、谁来写、怎么召回、错的记忆怎么办？
动手
用 Python 写一个记忆 MCP 服务（写入 / 检索 / 标记过期三个工具），通过 mcp-client 的 stdio 配置接进 dsh；跑「第一次踩坑 → 记下 → 第二次同类任务」两轮，比步数和成功率；故意写一条错记忆，看它会不会被盲信；对比「记忆放 MCP 按需查」和「直接写进 AGENTS.md」的上下文成本。
对照
learn-claude-code s09（筛选、提取、整理）；Know-how 地图 F3–F4（记忆谁写、冲突与遗忘，采用率约一成）；ACE（把上下文当可演化的 playbook）。

6 权限、审批与沙箱

40 分钟权限预设 · 审批协议 · sandbox · auto-review
动手
用 SDK 接管审批：读放行、工作区外写拒绝、rm 拒绝，表格列出每次审批；只靠沙箱看越界写在哪层被拦；工作区放带提示注入的 README 看哪层拦住；开实验包 auto-review（模型审动作）统计误放行和误拒绝。
对照
learn-claude-code s03；dsh-handbook 第 13 章。

7 钩子与扩展点：把软规则变硬

40 分钟补到 dsh 上hooks-claude-code · patch · 插件 waterfall
根本问题
写在 AGENTS.md 里的规则靠模型自觉；什么规则该升级成每次强制执行的检查？
动手
同一条规则三种写法对比遵守率：写进 AGENTS.md / Python PreToolUse 钩子拦截 / Stop 钩子在测试没过时强制再跑一轮（经 hooks-claude-code 桥）；用 patch 换模型、关工具、调压缩阈值。可选：用 TypeScript 写一个最小原生插件（需要 Node 24 + pnpm）。
对照
learn-claude-code s04；dsh-handbook 第 3–4 章；Know-how 地图 H2「怎样把约束做硬」。

8 规划与目标：先列计划，独立判断做完没

35 分钟todo · plan · goal · ralph
动手
多步任务四种跑法：直接 / /plan / /goal / 实验包 ralph（每轮全新子 agent），比完成度、步数、成本；plan 审阅时用 SDK 驳回一次看它怎么改。
对照
learn-claude-code s05、s17；learn-harness-engineering 第 7、9 讲（过早宣布完成）。

9 子 Agent、团队与 workflow

35 分钟subagent · team · workflow
动手
读很多文件的调研任务：单 agent vs 委托子 agent，比主上下文峰值、总 token、耗时、质量；用 workflow 工具写一个固定的扇出脚本，和让模型自己决定怎么拆对比。
对照
learn-claude-code s06、s13、s16。

10 长任务连续性：恢复、交接、干净收尾

35 分钟补到 dsh 上session · jobs · 钩子 + AGENTS.md
动手
运行中强制关掉运行时，用 resume_session 恢复；用 SessionStart / Stop 钩子实现「开工先读进度文件、收工必须写交接和清理现场」，对比有无交接时第二个会话的接续准确率（在 dsh 上复现 learn-harness-engineering 项目 03）。
对照
learn-claude-code s10–s12；learn-harness-engineering 第 5、6、12 讲。

11 观测：轨迹、会话库与反馈

30 分钟session-query · feedback · telemetry · timeline
根本问题
要改进 harness，先得能回答「它刚才为什么这样做」。
动手
用 session-query 的 SQLite 库查出前面所有课的会话，统计每类工具的调用次数、失败率、耗时；用 /feedback 和逐条评分记录几条人工评价，看它们存在哪、为什么「绝不进模型」；把一次失败的完整轨迹还原成时间线。
对照
Know-how 地图 B1「trace 怎么记才能拿来归因」；learn-harness-engineering 第 11 讲。

第二部分 · 让 harness 自己变好

沿用 Know-how 地图的 7 步闭环：采信号 → 归因分类 → 提议改动 → 验证 → 晋升 → 写回 → 维护退役。顺序有讲究：没有可靠的尺子，后面所有「改进」都无法验证，所以先做尺子。

12 尺子：可重复的评测，和什么才算真提升

45 分钟dsh 没有
根本问题
同一配置跑两次结果都不一样，改了一处凭什么说变好了？
动手
建 10 道可自动判分的任务（测试通过即对），分成训练集和留出集；同一配置跑 3 次算噪声线；做配对比较（同题对同题）；把评测目录放在 agent 改不到的位置（沙箱 + 权限只读），故意让 agent 有机会改测试，看防线是否生效。
对照
论文 Rethinking the Evaluation of Harness Evolution（必须对齐预算的基线 + 留出评测，否则分不清真提升和过拟合）；Know-how 地图 C、D 两类问题。

13 信号与归因：从失败轨迹找到 harness 的毛病

40 分钟dsh 没有
动手
从会话库取出第 12 课里失败的轨迹，让一个独立的诊断 agent 逐条读、按症状分桶（工具误用、上下文丢约束、过早停止、权限卡住……）并给出「是 harness 的问题还是模型能力问题」；人工抽查 5 条，算诊断准确率。
对照
HarnessFix（基于轨迹诊断再修 harness，比初始 harness 提升 6.3%–18.4%）；AHE（三根可观测支柱，让每次改动都成为可证伪的约定）。

14 提议与写回：一次失败该改哪一层

40 分钟dsh 没有
根本问题
同一个失败可以加一行 AGENTS.md、写一个 skill、记一条记忆、改工具说明、加一个钩子、或改编排；改哪层最划算、最不容易腐烂？
动手
挑第 13 课的 3 类失败，每类各在两层上做一次单变量修改（例如「软规则 vs 钩子」「AGENTS.md vs skill」），用第 12 课的尺子比较，记录每次改动挂的证据；用 ACE 的「生成 → 反思 → 整理」把经验写成可演化的 playbook（dsh skill 文件）。
对照
Know-how 地图「7 层对象」与 E、F 两类问题；ACE。

15 进化外循环：让 dsh 改自己的配置

60 分钟dsh 没有花钱最多的一课
动手
搭一个外循环：读失败轨迹 → 提议一个 patch（AGENTS.md / skill / 钩子 / 配置，每轮只改一处）→ 在训练集上评测 → 好于噪声线才接受，否则回滚 → 记账（本轮花费）。跑 3–5 轮，最后在留出集上验证；对比三种提议者：外部强模型、dsh 自己（Self-Harness 式）、随机改动的对照组。限制每轮改动大小，看能否减少过拟合。
对照
Meta-Harness（在 harness 代码上做外循环搜索，上下文 token 少 4 倍）；Self-Harness（agent 改进自己的 harness）；RRSI（约束提议与选择防止退化）；HarnessCompass（5 轮 Pass@1 54% → 66%，厂商自报）；The RSI Tax（改进本身的花费可能不值）。

16 闸门、退役与运行中自进化

45 分钟dsh 没有
根本问题
哪些改动可以自动生效、哪些要人批？规则越积越多怎么办？能不能在一次任务里就边做边改？
动手
给第 15 课的改动按风险分级（只读规则可自动、钩子与权限要人批），用 SDK 的审批协议实现人工闸门；统计每条规则的触发次数和贡献，退役没用的；试一次「运行中自进化」——允许 agent 在任务中给自己新建工具或 skill，看是帮了忙还是添了乱；最后对照 Know-how 地图的 L0–L4 成熟度给自己的配置定级。
对照
TTHE（测试时 harness 进化，难点是执行得来的代理信号是否可靠）；Live-SWE-agent（运行中自建工具）；Know-how 地图 H、I 两类问题。

运行方式与成本

  • 运行环境：本机。课程依赖加 deepseek-harness-sdk（自带运行时，macOS 14 arm64 有包，不需要系统 Node）；DSH_HOME 和工作区放在课程目录下，与本机其他配置隔离。
  • 模型：DeepSeek API（deepseek-v4-flash，本机已有 key）。真实的工具调用、缓存、压缩只有走真实 API 才看得到。「问 Claude」仍走本机 Claude。
  • 成本（推断，开写第 0 课时实测给准数）：第一部分每课几毛到一两元；第二部分的评测和外循环要反复跑整组任务，第 15 课单次外循环可能到十几元。课程工具里加「单格上限 + 整课上限」，超了停下等人确认。

还要你定的

  1. 花钱：这门课要调 DeepSeek API。建议上限：单格 2 元、整门课 60 元（第 15 课占大头）。可以按这个数，或给个你的数。
  2. 旧课去留：推荐新建「Agent Harness 实践（dsh）」并下线旧 agents-basics（学习记录留库不删）。
  3. TypeScript 插件（第 7 课可选格）：要不要在本机装 Node 24 + pnpm（用 fnm 装到用户目录，不动系统 Node）。不装也能学完。
