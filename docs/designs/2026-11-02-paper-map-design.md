# 论文脉络库：arXiv AI 论文的分类、关系与研究脉络（设计稿 2026-11-02）

- **分支**：`feat/paper-map`（基于 `feat/product-intel-design`，复用开源雷达的采集 → 标注 → 检索链路）。本稿 + 原型脚本，未接入平台页面。
- **一句话**：只收「有分量」的 arXiv AI 论文，越老门槛越高；每篇打上 类型 + 方向 + 检索标签 + builds_on；用户问「后训练」，就给出几条按时间演进的研究线，每个节点说明「相比前一步解决了什么」。
- **分类体系**：[app/modules/paper_taxonomy.json](../../app/modules/paper_taxonomy.json)（版本 `2026-11-02.1`）。
- **代码**：[_paper_collect.py](../../app/modules/_paper_collect.py)（S2 采集 + 门槛）、[_paper_label.py](../../app/modules/_paper_label.py)（标注 + Jev）、[_paper_map.py](../../app/modules/_paper_map.py)（脉络）、[scripts/paper_proto.py](../../scripts/paper_proto.py)（原型）、[tests/test_paper.py](../../tests/test_paper.py)。

## 0. 目标与完成标准

| # | 检查项 | 怎么验证 |
|---|---|---|
| P1 | 脉络覆盖：每个主题综述里公认的里程碑论文，出现在脉络输出（研究线 / 前置基础 / 综述）里的比例 ≥ 85% | `paper_proto eval`，GOLD 列表 41 篇，分 候选 / 入库 / 召回 / 选点 / 输出 五段统计，定位丢在哪一段 |
| P2 | 分类稳定：同一批论文打乱分批重标，类型一致 ≥ 0.85，二级方向一致 ≥ 0.80 | `paper_proto eval` 抽 400 篇 |
| P3 | 成本可控：原型 ≤ $3；全量一次性 ≤ $15，每月 ≤ $5；单次脉络 ≤ $0.01 | 每步记 DeepSeek 费用和 S2 调用次数 |
| P4 | 入库从严：总量控制在 1.2–1.5 万篇；近 6 个月的论文要有早期信号且过 Jev | 门槛统计（`stats()`） |

**通用性**：三个主题只是验收样本，链路不针对主题调参（主题检索式只用于原型的定向采集，全量走分领域切片，见 §2）。

## 1. 数据源结论

| | Semantic Scholar (S2) | OpenAlex |
|---|---|---|
| arXiv 论文被引 | 准（合并预印本与正式版） | **严重偏低**：DPO 293 vs 11,470；DeepSeekMath 101 vs 10,680；InstructGPT 4,208 vs 25,663 |
| 参考文献 | 有（`/paper/batch` 一次 500 篇） | arXiv 预印本常为 0 条（InstructGPT 0 条） |
| 检索 | bulk search 每页 1000，可按被引排序、按年份 / 领域 / 最低被引过滤 | 每次列表调用 $0.001，每天免费 $1 |
| 限流 | 无 key 走公共池，高峰期 429 很频繁；**免费 key 每秒 1 次** | key 已在 .env |

**结论**：S2 作主源（被引、参考文献、TLDR 都靠它）；OpenAlex 只作补充（作者机构、主题）。全量必须申请 S2 免费 key（见 §9 决策）。

## 2. 采集与入库门槛

**候选**：全量按「领域 × 年份」切片跑 S2 bulk search（`fieldsOfStudy=Computer Science`、按被引降序、带 `minCitationCount`），检索式来自分类体系各二级方向的 eg 词；原型只跑三个主题的检索式（每条按被引取 2 页 + 近期年份 1 页）。

**门槛**（[_paper_collect.decide](../../app/modules/_paper_collect.py)，越老越严）：

| 年龄 | 层级 | 条件 |
|---|---|---|
| ≤ 6 个月 | recent | 有早期信号（被引 ≥ 15 / 高影响力引用 ≥ 3 / 信息推荐里热门）**且** Jev 水文概率 < 0.5 |
| 6–24 个月 | young | 被引 ≥ 60 |
| 2–5 年 | mid | 被引 ≥ 250 |
| > 5 年 | old | 被引 ≥ 1000 |
| 任意 | near | 被引 ≥ 门槛 × 0.8 **且** 高影响力引用占比 ≥ 15%（入库论文平均约 11%）：刚好差一点、但同行实质引用比例高的（如 KTO） |
| 任意 | classic | 被库内 ≥ 8 篇引用且总被引 ≥ 500 的参考文献（不要求 arXiv，如 Attention / Adam 之前的经典） |

只收 arXiv 论文（classic 除外）。门槛是常量，调整只改一处，重跑 `admit_all()` 即可，不重新采集。

**水文甄别**：老论文靠被引就够（被引本身是同行投票）；难的是近 6 个月。两道筛子：① 早期信号（没人引、没人讨论的直接不收）；② Jev 判别（`noul` 概率，问题见 `JEV_Q`：套现成模型测一遍、换数据集重跑、堆提示词 → 是；新方法 / 新模型 / 扎实发现 / 有分量基准 → 否）。Jev 阈值需要用 50 篇人工标注校准（§9）。

## 3. 分类与标签

每篇一行 JSON（DeepSeek v4 flash，25 篇一批，8 路并发）：

- **k 类型**（单选）：method / model / survey / benchmark / dataset / empirical / theory / system / position / application。
- **d 主方向**（1 个二级类）+ **d2 副方向**（0–2 个）：10 个一级、49 个二级（预训练、后训练、推理效率、能力、Agent、知识检索、多模态、评测、安全、经典 ML）。
- **检索标签**：problem（要解决的问题）、method（方法术语原名）、bench（评测集）、base（基座模型）。
- **builds_on**：只能从这篇论文**库内参考文献**（按被引取前 15）里选它直接改进 / 沿用的，用编号 r0..r14 回填 s2id，模型无法编造不存在的边。
- **s**：中文一句话（做了什么 + 做法 + 结论）。

校验：code 不合法或缺字段的整行丢弃，漏掉的论文放宽规则重问一次。`label_src` = 标题 + 摘要 + 库内参考文献的哈希，内容和引用都没变就不重标；分类体系换版本则全部重标。全文索引：FTS5 trigram（标题、一句话、标签、摘要），中英文都能子串命中。

## 5. 脉络生成（[_paper_map.build](../../app/modules/_paper_map.py)）

1. **改写**：主题 → {must 核心说法, should 子方向名, domains 二级方向}，改写两次取并集（单次列哪些方向有随机性）。
2. **召回**：FTS 短语命中（must 1 分、should 0.4 分）+ 方向命中（主方向是主题首要方向 1.2、其它列出方向 1.0；副方向 0.5），≥ 1 分保留，按「相关度 + 0.25 × log 年均被引」取前 800。
3. **子图**：召回集合内的库内引用边；被 ≥ 8% 召回论文引用的库外前置基础（如 PPO 之于 RLHF）拉进来，最多 8 篇。
4. **选点**：PageRank 0.3 + 主题内被引次数 0.3 + log 年均被引 0.3 + 相关度 0.1（均取分位；用年均被引，新论文不因发表时间短吃亏）。**按子方向分名额**：名额 ∝ √(该方向里关键词命中主题的篇数)，改写没列出的方向合成一组、权重减半——避免大方向（如「后训练」里的推理 RL）挤掉其它方向的里程碑，也避免 MoE 主题把整个「架构」方向摊进来。共 68 篇，再给近 2 年论文留 12 个位置。
5. **成线**：选出的论文（年份、类型、一句话、问题、方法、on=它引用的库内编号）交给模型，分成 3–7 条技术路线，每个节点写「相比前一步解决了什么」。分数前 30 + 每个子方向第一名 + 前 3 个前置基础标 key，在问题开头列成「必须出现」；漏了带上一版结果补问一次；还漏就按引用边挂到关联最多的线上（role=相关，note 用标注的一句话），一条都不沾的放「其它重要工作」。只能用给定编号，编造的编号丢弃。结果按主题缓存，库更新后重算。

输出见原型结果 `map_*.md`。问答时：脉络直接回答「X 有哪些研究线」；「Y 问题有哪些解法」走 FTS 召回 problem 标签 + 按被引 / 脉络位置排序。

## 6. 与信息推荐复用

两边用 `arxiv:<id>` 作共同主键（信息推荐 `feed_items.id` 已是这个格式）。

- **信息推荐 → 论文库**：HF 每日论文 / AlphaXiv 热度、用户收藏 = 近期论文的早期信号（`mark_hot`）；收藏过的直接入库。
- **论文库 → 信息推荐**：推荐卡片直接用论文库的类型、方向、一句话（不再单独调模型），并加「所在脉络」链接（这篇在哪条研究线、前一步是谁）。
- 信息推荐偏实时和用户反馈，论文库偏经典和结构；同一篇论文从「热点」沉淀为「脉络节点」不需要重新处理。

## 8. 原型结果

数据：`paper_proto`（scratchpad 原型库，不碰正式库）。脉络样例：[paper-map-samples/](paper-map-samples/)（[后训练](paper-map-samples/map_posttrain.md) / [RAG](paper-map-samples/map_rag.md) / [MoE](paper-map-samples/map_moe.md)），取自最后一次评测。

**采集与门槛**（三个主题定向采集）：候选 26,476 篇 → 入库 2,128 篇（classic 845 / old 400 / mid 666 / young 915 / recent 147），库内引用边 58,115 条。第一轮无 key 采集 86 分钟（237 次 429 重试）；拿到 S2 key 后补采详情，限流基本消失。近期论文全部过 Jev。
- 修了经典回拉「滚雪球」：原来经典论文自己的参考文献也计数，第二轮多拉进 488 篇（经典到 1,597 篇）。改成只统计非经典论文的引用，已入库经典按同一规则重判，经典回到 845 篇；本身是 arXiv 论文的旧经典按年龄门槛重判，归入 old。

**标注**：补采后重标 840 篇 $0.10、94 秒（25 篇一批 × 8 路并发）；原型期间累计标注约 $0.63（含滚雪球那轮多标的 1,785 篇）。

| 检查项 | 目标 | 结果 |
|---|---|---|
| P1 里程碑出现在脉络输出 | ≥ 85% | 选点规则定型后连跑 3 次：35 / 35 / 36 篇（满分 41），即 **85.4%–87.8%**；最后一次后训练 14/16、RAG 12/13、MoE 10/12 |
| P2 分类一致性（400 篇打乱重标） | 类型 ≥ 0.85，二级 ≥ 0.80 | 类型 0.940、二级方向 0.882、一级方向 0.917 |
| P3 成本 | 原型 ≤ $3，单次脉络 ≤ $0.01 | 原型累计约 $1（标注 0.63、一致性 3 轮约 0.08、脉络调试约 0.25）；单次脉络 $0.0036–0.0041，18–26 秒 |

**仍然漏掉的里程碑**（分阶段定位，召回阶段 40/41 都在）：
- 数据缺口（1 篇）：BASE Layers（2103.16716）没被定向检索采到，上限是 40/41。
- 排序边界（2–3 篇）：KTO（2402.01306）在偏好优化组排第 76；LoRA（2106.09685）被标成 peft，不在后训练改写列出的方向里；HyDE（2212.10496）、Soft MoE（2308.00951）在组内排名靠后。这些属于「算不算该主题主线里程碑」的边界，不再针对性调参。

**调参记录**（都是通用规则，不针对单篇）：第一版 68%（次要方向没过召回线、选点偏老论文、成线漏 key）→ 次要方向 1.0 分后召回 39/41，但选点被摊薄（MoE 把整个架构方向拉进来）→ 名额改成按「方向内关键词命中篇数」分、主题外方向合成一组 → 加主题内被引次数和年均被引 → 必须出现的编号显式列出 + 兜底挂线 + 改写结果取并集 → 补采后 33/41：召回上限 800 截掉了 RLHF 这类只有方向分的高被引论文，上限放宽到 2000 → 主题外那组随之变大、挤占名额，权重封顶为最大主题方向的一半 → key 从 30 篇扩到 50 篇，并加上每个子方向前 3 名，波动从 29–35 收窄到 35–36。

## 10. 按需补充 + 每日热门入库（2026-11-03）

- **补单篇**：知识库「论文脉络」→「补充论文」，输入 arXiv 编号 / 链接 / S2 链接 / 标题。不看被引门槛直接入库（tier=manual，why=用户补充），当场标注，约 10–15 秒。`admit_all` 重算门槛时跳过 manual 和 classic。接口 `POST /api/kb/papers/add`。
- **补方向**：输入方向 → 改写成检索式（单独的缩写如 SNN 撞名多，不进检索式）→ S2 bulk 按年份切片检索 → 预览「会新增 / 接近门槛待判 / 库里已有」，**不写库**；用户确认后后台线程入库：按正常门槛判 → 近期论文过 Jev → 标注 → 重新生成这个主题的脉络。同一时间只跑一个，进度在 `paper_adds` 表；服务重启时正在跑的标为失败，可重新确认。接口 `POST /api/kb/papers/topic/preview`、`POST /api/kb/papers/topic/{id}/start`、`GET /api/kb/papers/topic/{id}`。召回少于 40 篇的脉络页会提示「补充这个方向」。
- **每日热门**：信息推荐刷新完 HF 每日论文 / AlphaXiv 后，近 14 天里出现过的 arXiv 论文：没入库的取详情，标 hot=1 走近期规则（热门即算早期信号，仍过 Jev 筛水文），入库的标注。开关 `paper.feed_ingest`（默认开）。同时修了 `mark_hot` 漏算 `hf:` 条目。
- **脉络召回三处修正**（补 SNN 时发现）：
  1. trigram 索引是子串匹配，ORM 命中 transformer、RAG 命中 storage、LoRA 命中 exploration：≤5 字符或全大写的单词命中后再按整词核对标题 + 摘要。RAG 关键词命中从 2,901 降到 184，LoRA 从 615 降到 140。
  2. 改写给的说法带括注（「GRPO (group relative policy optimization)」）整句当短语搜不到：括号外、括号里、斜杠两边各算一个短语。
  3. 方向分只给「关键词命中占该方向 ≥5%」的方向：SNN 被改写到 arch / cv 这类大方向时只占 1%，原来几千篇凭方向分进召回、按被引排完一篇 SNN 都没选上；现在只靠关键词召回（26 篇），线全是 SNN。MoE 去掉了 arch（3%），后训练 / RAG / LoRA / 推理 RL 的主方向都保留。
- **验收（副本库 8792）**：补单篇 IDGenRec 11.3 s、EAGER 12.4 s、已在库标题 2.9 s；补方向「脉冲神经网络」预览 74 s → 确认后 7 篇入库、7 篇标注、脉络重建，共约 140 s、$0.02；每日热门首跑 14 天积压 269 篇，入库 258、全部标注；7 个样例主题（后训练 / MoE / RAG / LoRA / 推理 RL / SNN / 生成式推荐）重建脉络，线名和节点均在主题内，每个 75–130 s、$0.008–0.018。

## 11. 每周维护（2026-11-03）

问题：之前只有每日热门自动入库。被引从不刷新，落选的论文永远不会重判；脉络也不知道自己已经过时；新论文入库后，引用它的老论文 builds_on 不会更新；失败只记在日志里。

机制（`app/modules/_paper_maintain.py`）：
- **刷新被引**：走 S2 batch，只取引用数（每次 500 篇），只 UPDATE cites / infl。
  - 每周只刷离门槛够近的落选论文：被引到当前年龄档门槛的 1/3（工业界按减半后的门槛算；近半年的论文看早期信号的 1/3）。
  - 每 28 天全量刷一次兜底：所有落选的 arXiv 论文，加上入库的近两年论文（经典和用户补充的除外；入库论文的被引只影响排序）。
  - 原因：第一次全量实跑刷了 49,558 篇，只有 46 篇有变化、0 篇新进库；约三分之二的落选论文离门槛很远，一周内不可能涨上来。
- **重判门槛**：只重判没入库的，够门槛就收进来，接着补详情、过 Jev（近期论文）。**已入库的不往外踢**：论文变老、门槛变高时不降级，只有 Jev 判为水文才降。
- **补标注**：走 `lab.todo()` 队列，包括新收的论文，以及参考文献里多了库内论文的引用方（label_src 变了，要重标 builds_on）。每次最多 1000 篇，剩下的下次接着标。
- **脉络不自动重生成**：生成时把召回集存进 `pool`，页面提示「自生成后相关论文多了 N 篇（新入库或重新标注）」，由用户决定要不要重新生成。
- **运行记录**：表 `paper_runs`（feed / weekly）。页面顶部显示最近一次每日入库和每周维护的结果；同一种运行连续失败 2 次就标红。服务重启打断的运行记为 failed。
