# 论文脉络库：arXiv AI 论文的分类、关系与研究脉络（设计稿 2026-11-02）

- **分支**：`feat/paper-map`（基于 `feat/product-intel-design`，复用开源雷达的采集 → 标注 → 检索链路）。本稿 + 原型脚本，未接入平台页面。
- **一句话**：只收「有分量」的 arXiv AI 论文，越老门槛越高；每篇打上 类型 + 方向 + 检索标签 + builds_on；用户问「后训练」，就给出几条按时间演进的研究线，每个节点说明「相比前一步解决了什么」。

## 0. 目标与完成标准

| # | 检查项 | 怎么验证 |
|---|---|---|
| P1 | 脉络覆盖：每个主题综述里公认的里程碑论文，出现在脉络输出（研究线 / 前置基础 / 综述）里的比例 ≥ 85% | `paper_proto eval`，GOLD 列表 41 篇，分 候选 / 入库 / 召回 / 选点 / 输出 五段统计，定位丢在哪一段 |
| P2 | 分类稳定：同一批论文打乱分批重标，类型一致 ≥ 0.85，二级方向一致 ≥ 0.80 | `paper_proto eval` 抽 400 篇 |
| P3 | 成本可控：原型 ≤ $3；全量一次性 ≤ $15，每月 ≤ $5；单次脉络 ≤ $0.01 | 每步记 DeepSeek 费用和 S2 调用次数 |
| P4 | 入库从严：总量控制在 1.2–1.5 万篇；近 6 个月的论文要有早期信号且过 Jev | 门槛统计（`stats()`） |

## 1. 数据源结论

| | Semantic Scholar (S2) | OpenAlex |
|---|---|---|
| arXiv 论文被引 | 准（合并预印本与正式版） | **严重偏低**：DPO 293 vs 11,470；DeepSeekMath 101 vs 10,680；InstructGPT 4,208 vs 25,663 |
| 参考文献 | 有（`/paper/batch` 一次 500 篇） | arXiv 预印本常为 0 条（InstructGPT 0 条） |
| 检索 | bulk search 每页 1000，可按被引排序、按年份 / 领域 / 最低被引过滤 | 每次列表调用 $0.001，每天免费 $1 |
| 限流 | 无 key 走公共池，高峰期 429 很频繁；**免费 key 每秒 1 次** | key 已在 .env |

**结论**：S2 作主源（被引、参考文献、TLDR 都靠它）；OpenAlex 只作补充（作者机构、主题）。全量必须申请 S2 免费 key（见 §9 决策）。

## 2. 采集与入库门槛

**候选**：全量按「领域 × 年份」切片跑 S2 bulk search（`fieldsOfStudy=Computer Science`、按被引降序、带 `minCitationCount`），检索式来自分类体系各二级方向的 eg 词；原型只跑三个主题的检索式（每条按被引取 2 页 + 近期年份 1 页）。

**门槛**（[_paper_collect.decide](../../app/modules/_paper_collect.py)，越老越严）：

| 年龄 | 层级 | 条件 |
|---|---|---|
| ≤ 6 个月 | recent | 有早期信号（被引 ≥ 15 / 高影响力引用 ≥ 3 / 信息推荐里热门）**且** Jev 水文概率 < 0.5 |
| 6–24 个月 | young | 被引 ≥ 60 |
| 2–5 年 | mid | 被引 ≥ 250 |
| > 5 年 | old | 被引 ≥ 1000 |
| 任意 | classic | 被库内 ≥ 8 篇引用且总被引 ≥ 500 的参考文献（不要求 arXiv，如 Attention / Adam 之前的经典） |

只收 arXiv 论文（classic 除外）。门槛是常量，调整只改一处，重跑 `admit_all()` 即可，不重新采集。

**水文甄别**：老论文靠被引就够（被引本身是同行投票）；难的是近 6 个月。两道筛子：① 早期信号（没人引、没人讨论的直接不收）；② Jev 判别（`noul` 概率，问题见 `JEV_Q`：套现成模型测一遍、换数据集重跑、堆提示词 → 是；新方法 / 新模型 / 扎实发现 / 有分量基准 → 否）。Jev 阈值需要用 50 篇人工标注校准（§9）。

## 3. 分类与标签

每篇一行 JSON（DeepSeek v4 flash，25 篇一批，8 路并发）：

- **k 类型**（单选）：method / model / survey / benchmark / dataset / empirical / theory / system / position / application。
- **d 主方向**（1 个二级类）+ **d2 副方向**（0–2 个）：10 个一级、49 个二级（预训练、后训练、推理效率、能力、Agent、知识检索、多模态、评测、安全、经典 ML）。
- **检索标签**：problem（要解决的问题）、method（方法术语原名）、bench（评测集）、base（基座模型）。
- **builds_on**：只能从这篇论文**库内参考文献**（按被引取前 15）里选它直接改进 / 沿用的，用编号 r0..r14 回填 s2id，模型无法编造不存在的边。
- **s**：中文一句话（做了什么 + 做法 + 结论）。

校验：code 不合法或缺字段的整行丢弃，漏掉的论文放宽规则重问一次。`label_src` = 标题 + 摘要 + 库内参考文献的哈希，内容和引用都没变就不重标；分类体系换版本则全部重标。全文索引：FTS5 trigram（标题、一句话、标签、摘要），中英文都能子串命中。

## 5. 脉络生成（[_paper_map.build](../../app/modules/_paper_map.py)）

1. **改写**：主题 → {must 核心说法, should 子方向名, domains 二级方向}（一次小调用）。
2. **召回**：FTS 短语命中（must 1 分、should 0.4 分）+ 方向命中（主方向 1.2 / 0.9、副方向 0.5），≥ 1 分保留。
3. **子图**：召回集合内的库内引用边；被 ≥ 8% 召回论文引用的库外前置基础（如 PPO 之于 RLHF）拉进来，最多 8 篇。
4. **选点**：PageRank（引用方 → 被引方）45% + log 被引 35% + 相关度 20%（均取分位）选 50 篇，再给近 2 年论文留 10 个位置。
5. **成线**：选出的论文（年份、类型、一句话、问题、方法、on=它引用的库内编号）交给模型，分成 3–7 条技术路线，每个节点写「相比前一步解决了什么」。只能用给定编号，编造的编号丢弃。结果按主题缓存，库更新后重算。

输出见原型结果 `map_*.md`。问答时：脉络直接回答「X 有哪些研究线」；「Y 问题有哪些解法」走 FTS 召回 problem 标签 + 按被引 / 脉络位置排序。

## 6. 与信息推荐复用

两边用 `arxiv:<id>` 作共同主键（信息推荐 `feed_items.id` 已是这个格式）。

- **信息推荐 → 论文库**：HF 每日论文 / AlphaXiv 热度、用户收藏 = 近期论文的早期信号（`mark_hot`）；收藏过的直接入库。
- **论文库 → 信息推荐**：推荐卡片直接用论文库的类型、方向、一句话（不再单独调模型），并加「所在脉络」链接（这篇在哪条研究线、前一步是谁）。
- 信息推荐偏实时和用户反馈，论文库偏经典和结构；同一篇论文从「热点」沉淀为「脉络节点」不需要重新处理。
