# 三项核心能力：判断力 / 思考深度 / 多领域学习（设计稿）

> 基线分支：`feat/kb-judgments`（判断台账，未合并 main）——本设计在它上面接续。
> 2026-11-03 按反馈修订：① 判断要能引用看过的材料（也可自己指定源或没有源）——**已实现**；② 想法打磨加「批判者」角色，只给认知和追问、不给结论；③ 领域档案直接绑定深度学习的计划和深读条目。

## 0. 结论先行

不新开独立板块或服务。三项能力都是在已有链路上**补「先下判断 → 事后对答案 → 计分」的闭环**：

| 能力 | 主落点 | 复用的现有部件 | 要新增的核心 |
|---|---|---|---|
| 判断力 | 知识库 ›「判断」台账（已是首页）升级为「判断训练」 | `kb_judge` 的复查周期 / 只追加的复查记录 / 问题线；深读追问清单；Deep Dive 的「选中方案 vs 朴素替代」实验；产品雷达 TrustMRR 收入快照；调研板块 | 4 种「先判断后揭晓」的出题入口 + **联网核验** + 判断力计分（命中率、校准度、提前量） |
| 思考深度 | 知识库 › 新标签「想法」（问题线的升级版） | 问题线、概念图谱、批注、判断台账 | 固定 6 层的深度树 + 苏格拉底式追问 + 新材料自动「回炉」 |
| 多领域学习 | 深度学习 › 新标签「领域档案」 | 三轮学习计划、章末测试（理解 / 判断 / 应用三个维度）、按需加一节 | 领域等级量表 + **专家水平评测**（盲测新论文 / 新产品 / 争议题，和真实结果、专家立场对照） |

三者用同一份数据串起来：所有「我的判断」都写进 `kb_judgments`（加 `domain / kind / confidence% / verify_by / source` 字段）。判断力的分数按领域聚合，就是领域档案里「判断」那一项；想法树里第 6 层的可证伪预测也会进台账，到期了一起复查。

## 1. 判断力

### 1.0 依据材料（已实现，2026-11-03）

每条判断都可以带「依据材料」，三种情况都支持：
- **看过的材料**：记判断时在输入框里搜，范围是深读条目（论文 / 项目 / 文章）、调研文档、读书、学习计划、点赞或收藏的信息，结果按时间倒序。存的是材料的 sid，能点回原文。
- **自己指定的源**：贴链接，或写一句出处（比如「某次分享里听到的」）。
- **没有源**：直接写判断，Agent 评价时会注明这条是凭经验或直觉。

依据材料会写进 Agent 归类和评价的上下文：`basis` 要说清这些材料撑不撑得住这个判断。复查时，引用过的材料排在证据最前面。
数据存在 `kb_judgments.sources`（JSON），接口是 `GET /api/kb/materials?q=` 和 `POST /api/kb/judgments {sources}`。
后面各个出题入口（论文「为什么不」、盲评、下注卡）都会自动带上当前材料作为依据。

### 1.1 四种出题入口（都是先写判断、再揭晓答案）

1. **论文：「为什么不 XX」**（深读页，读完方法之后、看实验之前）
   - 页面先只给问题、动机和方法；用户写 1–3 条「为什么不用 XX / XX 会不会更好」，并给出置信度。
   - 先揭晓第一层：论文自己的消融实验或讨论里有没有回答。
   - 第二层核验（后台任务，联网）：沿 Semantic Scholar / OpenAlex 的引用链和 arXiv 检索后续论文，看有没有人做过 XX，结论是 ✅ 有效 / ❌ 无效 / ➖ 无定论 / ⏳ 还没人做。
   - 「还没人做」的条目自动变成预测，按 90 / 180 / 365 天复查。**这是最有价值的一类**：说明你比领域先想到了这个方向。
   - 已实现（第一版）：深读论文页「为什么不」面板（替代方案 + 猜 更好/差不多/更差/说不准 + 信心 + 理由），同时记进判断台账（依据材料 = 这篇论文）。
     第一层 DeepSeek 读 PDF 全文 + 深读笔记；第二层 S2 取引用它的前 2000 篇 + 关键词检索 → 关键词粗排前 40 篇 → DeepSeek 读摘要判定（XX 更好 / 差不多 / XX 更差 / 有条件 / 还没人做）带引用。
     「还没人做」写一条 90 天后的改期复查。判断页显示命中率（有条件算半个）/ 已回答 / 还没人做。暂未做：隐藏实验部分再作答、180/365 天梯度、提前量天数。
2. **开源项目：盲评设计**（Deep Dive 的 understand 阶段结束后）
   - 从 `understanding.md` 的「设计决定」里取 3 个，只给场景、约束和候选方案，不说项目选了哪个。
   - 用户选一个方案，或提出自己的方案并写理由。
   - 揭晓三样东西：项目实际选了什么、experiment 阶段的对照数据、项目后来有没有改掉这个设计（查 issue / PR / CHANGELOG 里的 migration、rewrite、deprecate）。
   - 计分：和作者一致且有数据支撑得 1 分；不一致但项目后来改成你的方案，或者实验证明你的方案更好，得 1.5 分（看得比作者远）。
3. **产品：下注卡**（产品雷达 / 初创库的公司卡片上）
   - 两种题型：「这个产品 6 个月后 MRR 会涨 / 平 / 跌」，以及「它为什么不做 XX」（或者「做 XX 的竞品会赢」）。
   - 核验：TrustMRR 收入快照已经有了，可以自动判定；「为什么不」类到期后在初创库里查有没有新公司做了 XX，以及它们的数字怎样。
4. **趋势：预测**（任意页面的「记判断」，或者调研报告读完后）
   - 必须写清期限、可判定标准和置信度；写得模糊的，由 Agent 改写成可判定的说法，你确认后才入库。
   - 到期时自动派一个调研任务（DeepResearch 风格，联网），给出带来源的结论，你确认 holds / overturned。

### 1.2 计分（「判断」页顶部 + 每周写进复盘）

- **命中率**：按领域（算法 / 工程 / 产品 / 趋势）× 题型分别统计。
- **校准度**：用 Brier 分数比较你写的置信度和实际结果，画「置信度 vs 实际命中率」曲线，看出自己系统性地过度自信还是不够自信。
- **提前量**：「为什么不」里后来被别人验证有效的条数，以及你下判断到首篇验证论文发表之间隔了多少天。
- **对照基线**：同一道题让 Agent 不看答案也下一次判断，你赢 Agent 的比例。避免只跟自己比。

### 1.3 现有判断台账要改的

- 复查目前「不联网」→ 为预测类和「为什么不」类增加联网核验（走调研板块的引擎，每条设成本上限）。
- 复查结论仍然只追加；Agent 的核验结论只作参考，由你来定 verdict。

## 2. 思考深度：「想法」

### 2.1 一个想法 = 一棵 6 层深度树（每层可以有多个版本，只追加）

| 层 | 要回答的 | 合格标准（Agent 按这个打分） |
|---|---|---|
| L1 主张 | 一句话说清我认为什么 | 可被反对，不是同义反复 |
| L2 机制 | 为什么成立，因果链是什么 | 每一环都有证据或标明是假设 |
| L3 前提 | 依赖哪些假设，哪个最脆弱 | 至少 3 条，并标出最脆弱的那条 |
| L4 反方 / 边界 | 最强反方（steelman）、在哪些条件下不成立 | 反方要强到让你犹豫 |
| L5 第一性 / 迁移 | 把它还原到更底层的原理，能迁移到哪两个别的领域 | 迁移后的推论非平凡 |
| L6 推论 / 行动 | 可证伪的预测，以及我因此要做什么 | 预测自动进判断台账 |

### 2.2 批判者：给认知、不给结论

想法页常驻一个**批判者**角色。它的规矩：
- 每一轮只输出三样东西：
  1. **一个认知**：这个想法里被忽略的视角、反例或隐含前提，比如「你默认了数据是独立同分布的」。只指出，不下「所以你错了 / 对了」的结论。
  2. **一个引导问题**：指向最薄弱的那一层，问得具体到能去求证。
  3. **去哪求证**：优先从你看过的材料里挑；没有的话，给出该搜的方向或该做的小实验。
- 不替你写答案，不改写你的主张，也不给最终结论。你追问「那答案是什么」时，它只再给一条线索。
- 这一轮的状态变成「待求证」。你去学习、求证之后，提交新版本，附上求证材料（用 1.0 的依据材料选择器）和这次改了哪一层。
- 批判者再看下一轮：新版本有没有回应上一轮的质疑。有的话，这一层的深度分涨；回避了的话，就继续追问这一层。
- 所有轮次只追加，能回看「我第 3 轮被问到 X，去读了 Y，把 L3 改成了 Z」。

### 2.3 持续打磨的机制

- **追问**：由批判者执行（见 2.2）。
- **回炉**：知识库新进的材料（深读、调研、信息推荐里收藏的）命中这个想法的概念时，Agent 判断它支持还是挑战某一层，挑战的进「待回炉」列表。
- **深度分**：6 层各 0–3 分，在版本历史里看分数怎么涨。L6 预测的兑现结果反过来校验 L2、L3（预测错了，说明机制或前提有问题）。

### 2.4 设多少个方向

建议常驻 **6–9 个根问题（3 个领域 × 2–3 个），同时活跃打磨的不超过 3 个**。多了每个都浅，违背「深度」本意。默认三个领域：AI 算法 / 模型、Agent 与工程、AI 产品与增长；根问题由你来定（第一次打开时，Agent 从你已有的问题线里挑出候选）。

## 3. 多领域学习：「领域档案」

### 3.0 和深度学习绑定

- **领域**就是深度学习里的一个分组：建学习计划、深读论文 / 项目、加书的时候选（或由 Agent 建议）所属领域；老的计划和条目由 Agent 批量建议归属，你确认后生效。
- 领域档案页聚合这个领域下的所有内容：
  - 计划进度和章末测试分数（理解 / 判断 / 应用三个维度）；
  - 深读条目的追问作答；
  - 这个领域的判断和复查结果（来自判断台账，依据材料是这个领域的内容，就自动归到这个领域）；
  - 这个领域的想法树。
- 联动是双向的：
  - 学习这一侧产出的作答、测试、判断，自动进领域档案计分；
  - 领域考查出的最弱项，回写成学习计划的调整，或「按需加一节」；
  - 盲测题优先取这个领域的新论文（来自信息推荐和 AlphaXiv）。

### 3.1 等级量表（每个领域一张）

L1 入门（能复述）→ L2 熟练（能解释机制、做对章末测试）→ L3 能判断（能对新方案给出有依据的判断，和专家立场一致率高）→ L4 专家（盲测预测新论文、新产品的结果，明显好于基线；能提出被后来验证的「为什么不」）→ L5 能出题（能出让 L3 答错的题，能讲清领域里的开放问题和各方立场）。

### 3.2 专家水平评测（「领域考」，每个领域每月一次，约 30 分钟）

1. **知识**：从章末测试题库抽题（已有）。
2. **盲测**：拿 3 篇近 1–3 个月的新论文，只给摘要的前半部分和方法，让你预测主要结果、审稿意见（用 OpenReview 有分数的论文）；再拿 2 个新产品，预测增长。和真实结果对照。
3. **争议题**：领域里专家意见分歧的问题（从一线人物的公开表态里整理），你表态后，展示你和各位专家的立场分布。
4. **为什么不**：直接取这个领域在判断力模块里的历史得分。

四项加权得到等级，并指出最弱的一项；薄弱点回流到学习计划，用已有的「按需加一节」和计划调整。

### 3.3 快速跨领域

- 新领域的学习计划第一轮之前加一张**迁移卡**：用你已有领域的概念类比新领域的 20 个核心概念，标出哪些类比会误导。
- 三轮计划不变；第二轮（会判断）里的练习改为从判断力模块出题，第三轮结束后自动安排第一次领域考。

## 4. 目标 / 约束 / 清单 / 输出物

**完成标准（使用者能感知的）**
- 读一篇论文时，能写下「为什么不」并在 10 分钟内看到第一层揭晓；后台核验在 30 分钟内给出带引用的后续论文结论。
- 判断页能看到 4 类题的命中率、校准曲线和提前量。
- 「想法」能建树、被追问、看版本和深度分；新材料进来后 24 小时内出现在「待回炉」里。
- 领域档案能完成一次领域考，给出等级和最弱项，并回流到计划。
- 验证样例固定覆盖：2 篇论文（1 篇有后续工作、1 篇较新）、1 个 GitHub 项目、1 家初创公司、1 条趋势预测、1 个想法、1 个领域。在 8780 的真实链路上跑，由程序计时。

**约束**
- 不新增独立服务或 Agent，只在知识库和深度学习板块里加标签，后台任务走现有的 jobs。
- 学习记录、判断、复查一律只追加，改动 schema 前先查库。
- 联网核验每条成本 ≤ $0.3、每天 ≤ $3（可在设置里调）。
- 已有页面的观感不变，新 UI 先出截图确认。

**清单（建议顺序）**
0. ✅ 判断引用依据材料（看过的 / 自定 / 无源）
1. ✅ P0 判断力 ①「为什么不」+ 引用链核验 + 计分骨架（2026-11-03，`app/kb_whynot.py` + `web/modules/_whynot.js`；ReAct 实测两层共 21–41 秒）
2. ✅ P0 判断力 ④ 趋势预测联网复查（2026-11-03，`app/kb_verify.py`：到期预测在知识库整理时自动派后台调研任务，观点 / 评价可在详情里手动点「联网核验」；Agent 先落可判定标准再找正反证据，给出带来源和日期的参考结论，复查结论仍由我写；记录只追加。默认每天自动 ≤ 5 条、同一条 30 天内不重复、standard 档模型，设置 `kb.verify` 可调；jobs 表不记花费，美元上限用条数近似。「为什么不」里「还没人做」的到期改为重跑后续论文核验。SWE-bench 预测实测：自动派发 → 57 秒出结论，4 条来源，并指出口径模糊。未做：下判断时把模糊预测先改写成可判定标准再入库，目前在核验时由 Agent 补标准）
3. P1 判断力 ② 开源盲评、③ 产品下注卡
4. P1 想法深度树 + 批判者（给认知不给结论、待求证 → 新版本）+ 回炉
5. P2 领域档案（绑定计划 / 深读 / 读书）+ 领域考
- 审批节点：第 1 项的页面截图确认、第 4 项的根问题列表确认、合并 main 之前。
