Agent Harness 实践课提纲 v1

重做「实践」TAB 里的 Agent 课（原 agents-basics 0–6）。主线：DeepSeek Harness（dsh），用它的官方 Python SDK 在课程页面里逐格驱动。其余项目只做辅助对照。2026-11-27

一句话：每课拆 dsh 的一个 harness 环节，固定四步——读它的源码位置 → 用 SDK 跑一次看现象 → 改一个配置或插件再跑 → 量出差别。learn-claude-code 的同名章节作为「100 行最小实现」对照，帮你看清机制本身；dsh-handbook 提供中文踩坑与实测数字。

为什么要重做

旧课 7 节、每节 2–3 格，问题不在格子少，而在摸不到真正的 harness：工具调用是让本机 Claude 按 JSON 文本协议「演」出来的，没有原生 tool_use、没有前缀缓存、没有自动压缩、没有审批和沙箱，循环、记忆、子 Agent 都是课程里手写的玩具版。学完知道概念，但不知道生产级 harness 里这些环节长什么样、改了会怎样。

所以新课换成「拿一个真实、开源、可拆的 harness 当标本」。

主线选型：为什么是 dsh

入选候选的标准：开源、2026 年仍在活跃更新、能在本机跑、harness 各环节可以单独替换或观察。按这条筛出四个，比较的轴是「离生产有多近」和「改一个环节要动多少东西」：

项目是什么离生产改一个环节本机能跑定位
deepseek-ai/deepseek-harness（dsh）DeepSeek 官方 Agent 运行时，2026-08-13 开源，MIT，TypeScript；「一切皆插件」，能力拆成 50 多个包生产级（官方 CLI / Web / 桌面都基于它）换一个 patch 文件或插件，不动核心能：pip install deepseek-harness-sdk 自带运行时（有 macOS 14 arm64 包），不需要系统 Node；用 DeepSeek API主线

读表要点：learn-claude-code 讲机制最清楚，但它是教学重写，不会遇到真实系统的约束（缓存前缀、压缩后约束丢失、审批流、沙箱后端）；dsh 是生产系统，而且把每个环节拆成了独立的包和扩展点，正好「一课一个包」。所以主线用 dsh，看不懂某个机制时翻 learn-claude-code 同名章的 100 行版本。其他参考过但不进课的：claude-code-from-scratch（TS 版重写，和 learn-claude-code 重叠）、12-factor-agents（原则清单，第 11 课引用）、how-to-build-a-coding-agent（Go 版最小 agent）、claw0（偏聊天网关）。

全景：dsh 的 harness 分层与课程映射

按「一个请求从进来到结束要经过什么」分四层，每层对应几个 dsh 包。课程按层推进：先让循环转起来，再管上下文，再管边界，最后管质量和长期运行。

逐课提纲

每课骨架：根本问题 → dsh 怎么做（源码位置）→ 动手实验（可量化的现象）→ 辅助对照 → 坑。实验全部通过 SDK 在页面格子里跑，工作区是课程自带的一个小仓库（带测试、带种子 bug），结果用 ss 可视化（轨迹、表格、柱状图）。

0 开课：模型 + harness，各管什么

约 20 分钟sdk-minimal vs sdk
根本问题
同一个模型，为什么换个 harness 表现差很多？harness 到底包了哪些东西？
动手
装 SDK，隔离的 DSH_HOME；同一个任务（修一个带测试的小 bug）分别用 sdk-minimal（只有 shell + 压缩）和完整 sdk profile 跑，比较：工具清单、步数、token、是否通过测试。打印两个 profile 的配置树，标出多出来的每个包。
辅助
learn-claude-code README「Agent = 模型 + Harness」；learn-harness-engineering 第 1–2 讲。
坑
dsh-handbook 正文基于 0.1.x，命令要以 0.2.x 官方文档为准；SDK 不会读 ~/.dsh，必须显式给 home。

1 循环：一轮对话里到底发生了什么

约 30 分钟core/agent-loop
根本问题
Agent 的「自主」只是一个 while 循环吗？它靠什么决定继续还是结束？
dsh 怎么做
读 packages/core/agent-loop 的 agent.ts（请求 → 流式解析 → 工具执行 → 结果回填 → 再请求）和 inbox.ts（运行中插入的消息怎么进循环）。
动手
用 on_notification 订阅事件，把一次运行画成轨迹（每步：模型请求、工具名、耗时、token）；改 max_tokens、给一个做不完的任务，观察 finish_reason 的几种取值；运行中途用 steer 插一句话，看它从哪一步生效。
辅助
learn-claude-code s01：30 行循环 + bash，和 dsh 的轨迹逐项对应。

2 工具：模型看到的工具，和真正执行的

约 35 分钟core/tools · tool-executor-native / ptc · fs · shell
根本问题
工具描述、返回格式、执行方式各怎么影响成功率和成本？
dsh 怎么做
原生工具调用 vs PTC（Code mode：模型写一段代码一次编排多次工具调用）；core/agent-tool-presentation 决定模型看到的工具说明。
动手
同一个多文件检索任务分别用 native 和 PTC 执行器，比请求次数、总 token、耗时；用 patch 关掉一个文件工具，看模型怎么用 shell 绕过去；让工具返回报错，看模型怎么恢复。
辅助
learn-claude-code s02（加一个工具只加一个 handler）；dsh-handbook 第 8 章 8.2–8.3.1。

3 上下文与缓存：每次请求喂了什么、花了多少钱

约 35 分钟context · core/system-prompt · llm
根本问题
上下文由哪些部分拼成？为什么「前缀稳定」能让成本降一个量级？
dsh 怎么做
context 包注入工作区指令（AGENTS.md）、时间上下文、引用；DeepSeek 前缀缓存按「从头开始一致的部分」计费。
动手
把一次请求的上下文按来源拆块画成堆叠柱（系统提示 / 工具定义 / 指令文件 / 历史 / 本轮输入）；连续跑 5 轮，记录缓存命中 token 和费用；故意在系统提示开头插时间戳破坏前缀，再跑 5 轮对比。改 AGENTS.md 里一条规则，看它是否被遵守。
辅助
dsh-handbook 第 14 章（实测命中率 97% 的条件）；learn-harness-engineering 第 4 讲（一个巨型指令文件为什么失败）。

4 上下文满了：大输出转存与压缩

约 40 分钟spill · compaction-basic · compaction-tool-result-pruner
根本问题
长任务必然撑满上下文，丢什么、留什么、丢了会出什么事？
dsh 怎么做
spill 把超大工具输出落盘只留路径；tool-result-pruner 先裁旧工具结果；compaction-basic 生成历史摘要；/compact 手动触发。
动手
让工具吐 200KB 日志，看 spill 后模型拿到什么、还能不能取回原文；跑一个长会话触发自动压缩，压缩前后各问一次早期约定的约束（如「不许改 tests/」），统计遵守率——复现「压缩会悄悄抹掉安全约束」的现象；换压缩策略（patch）再比。
辅助
learn-claude-code s08 四步压缩（转存 → 裁剪 → 微压缩 → 摘要，切点要保护 tool_use / tool_result 配对）；论文 Governance Decay: How Context Compaction Silently Erases Safety Constraints（2026，本地论文库）。

5 规划与目标：先列计划，独立判断做完没有

约 35 分钟todo · plan · goal
根本问题
Agent 常见两种失败：走哪算哪、过早宣布完成。harness 用什么机制拦？
dsh 怎么做
todo 工具；/plan 先出计划、审阅后再执行；/goal 每次准备停止时由独立判断决定是否继续，目标不可能或超上限时交还用户。
动手
一个多步任务三种跑法：直接跑 / /plan / /goal，比完成度（测试通过数）、步数、成本；在 plan 审阅时用 SDK 驳回一次，看它怎么改。
辅助
learn-claude-code s05、s17；learn-harness-engineering 第 7、9 讲。

6 权限、审批与沙箱

约 40 分钟preset · sandbox · 审批协议 · guard
根本问题
给 Agent 多大权限？谁来批？批错了还有没有最后一道防线？
dsh 怎么做
三层：权限预设（permission_mode）→ 审批流（approval/request，SDK 可接管）→ 沙箱（macOS 用 Seatbelt）；guard 里的重复调用提醒和超时策略。
动手
用 SDK 写一个审批处理器：读操作放行、写工作区外拒绝、带 rm 的命令拒绝，跑一个会触发这些操作的任务，表格列出每次审批；关掉审批只靠沙箱，看越界写文件在哪一层被拦；在工作区放一个带提示注入的 README，看它是否被执行、哪层拦住。
辅助
learn-claude-code s03；dsh-handbook 第 13 章（三层安全、插件审计清单）。

7 扩展点：不改核心，改行为

约 45 分钟profile · cordis.patch.yml · 插件 waterfall
根本问题
想给 harness 加规则（如每次请求前检查、工具前后记录），该 fork 还是挂钩子？
dsh 怎么做
profile 是配置栈，patch 文件按顺序叠加；插件接入 agent/request 等 waterfall。
动手
先只用 patch：换模型、关工具、调压缩阈值，每个改动一格对比；再写一个最小插件（每次请求前注入一条提醒 + 记录工具调用），用 dsh plugin add file: 装进隔离 home，跑任务验证生效。
辅助
learn-claude-code s04 Hooks；dsh-handbook 第 3–4 章（插件开发三层测试）。
坑
写插件要 pnpm 和 Node ≥ 24（本机现在是 23.11）；只用 patch 不需要。

8 技能与 MCP：能力按需加载

约 30 分钟skill · mcp
根本问题
能力越加越多，全塞进提示词会怎样？
动手
准备 10 个技能，对比「全文塞系统提示」和「只给目录、用到再加载」的上下文 token 与正确率；接一个本地 MCP server（课程自带的小服务），看它的工具怎么并入同一个工具池。
辅助
learn-claude-code s07、s14；dsh-handbook 第 9 章 9.1、9.6。

9 子 Agent 与团队：拆任务、隔离上下文

约 35 分钟subagent · team
根本问题
什么时候该拆给子 Agent？拆了省的是什么、多花的是什么？
动手
一个需要读很多文件的调研任务：单 Agent vs 委托子 Agent，比主上下文 token 峰值、总 token、耗时、答案质量；用 team 任务板让两个 Agent 认领任务，看冲突怎么处理。
辅助
learn-claude-code s06、s13；dsh-handbook 第 9 章 9.2、9.7。

10 长期运行：会话恢复、后台作业、定时

约 30 分钟session · jobs · schedule
根本问题
任务跨越多个会话、中途被打断，怎么接上？
动手
运行中强制关掉运行时，用 resume_session 恢复，看它怎么修复被中断的一轮；后台跑一个慢命令，主循环继续做别的；对比「有交接文件（进度日志）」和「没有」两种情况下第二个会话的接续准确率。
辅助
learn-claude-code s09–s12；learn-harness-engineering 第 5、12 讲，项目 03（多会话连续性）。

12 综合：做一次 harness 工程对照实验

约 45 分钟复现 learn-harness-engineering 项目 01 / 05
根本问题
把前面学的机制组合起来，到底能提升多少？
动手
同一组任务三种配置：只有提示词 / 加 AGENTS.md + 验证命令 / 再加 plan + goal + 独立评估者；用第 11 课的评测框架量化，写出自己的结论和下一步改什么。

运行方式与成本

  • 运行环境：本机（课程 runtime 仍是 local）。课程 pip 加 deepseek-harness-sdk；工作区和 DSH_HOME 放在课程目录下，与本机其他配置隔离。
  • 模型：DeepSeek 官方 API（deepseek-v4-flash，本机已有 DEEPSEEK_API_KEY）。与旧课不同，这门课不走本机 Claude——要看原生工具调用、缓存命中、压缩这些真实行为，必须走真实 API。
  • 成本：按每格几次到几十次请求估算，整门课约几元人民币（推断，开写第一课时实测一格后给准数，并在每格输出里显示本格花费）。
  • 「问 Claude」照常走本机 Claude，不受影响。

需要你定的

  1. 主线框架：推荐 dsh（生产级、可拆、有 Python SDK）。备选是以 learn-claude-code 为主线（纯 Python 从零写，机制更透明，但接触不到真实系统的约束）。主线定了之后改动返工大，请先确认。
  2. 花钱：这门课要调用 DeepSeek API，预计整门几元。确认可以用、以及是否要设上限（建议在 ss 里加单格和整课的花费上限）。
  3. 第 7 课插件开发：需要在本机装 Node 24 + pnpm（只影响这一课）。选项：装（推荐，用 fnm 装到用户目录，不动系统 Node）/ 不装，第 7 课只做 patch 配置。
  4. 旧课去留：推荐新建一门「Agent Harness 实践（dsh）」并下线旧 agents-basics（旧课的学习记录保留在库里不删）。备选：保留旧课作为入门。
