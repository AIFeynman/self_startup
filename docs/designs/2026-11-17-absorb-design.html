大量信息的吸收设计

2026-11-17 · 方案稿，未动代码 · 数字来自 data/app.db 和 data/kb 的只读盘点

结论：问题不在排序，在阅读的单位。现在的单位是“一条内容”，你一天能看约 6 条，而库里每天进来几百上千条。把单位换成“一个问题上的认知变化”，一条变化背后可以挂几十上百条来源，你看 15–20 条变化就等于过了上千条内容。系统只给你看三种东西：新的、被加强的、被挑战的；重复的折叠成证据数。

1. 现状：输入和吸收差了两个数量级

输入（库里已有）约 27 万条
  • X 长文 97,785 篇，其中 8,814 篇已分析
  • 论文 99,604 篇，其中 13,577 篇已打标签
  • GitHub 项目 66,745 个，已打标签
  • 信息推荐 8,938 条（X 讨论、博客、论文、Reddit、视频、产品等 14 类）
  • 产品雷达 2,350 家公司、445 个事件、718 条增长案例
吸收（你留下的痕迹）约 6 条/天
  • 阅读记录 102 条，跨 18 天
  • 信息推荐反馈 57 条，其中赞/踩 0 次，隐藏 3 次
  • 知识库 11 个主题、192 个概念
  • “我的判断”数据库里 1 条，知识库判断页 23 个

这说明三件事：

  • 排序解决不了。排序只是决定“看哪 6 条”，其余 99% 仍然没被吸收，而且排序没有你的反馈可学（赞踩为 0）。
  • 内容高度重复，但重复被当成了负担。上一轮 38 篇 harness 文章里，8 篇是同一个标题的不同版本。重复本该是“这个说法有多少人支持”的信号。
  • 已经有骨架，但没用来组织输入。知识库的 11 个主题、192 个概念是你自己的知识结构，但五个信息源各自按时间和热度排，没有挂到这个骨架上。

2. 设计依据：人是怎么吸收大量信息的

认知规律对设计的要求
工作记忆一次只装 4 个左右的块每一屏、每一层不超过 5–7 项；靠分层打包，不靠长列表
新知识要挂在已有结构上才记得住以你已有的主题和问题为骨架，新内容显示为“相对你已知的变化”，不显示为孤立条目
意外才驱动学习，确认不驱动优先展示改变你看法的内容（新的、相反的）；只是重复你已知的，折叠成数字
主动生成比被动阅读记得牢先让你表态或预测，再给证据；每周产出自己的判断
人先记要点，细节按需取四层逐级展开：一句话结论 → 条件和依据 → 各来源说法 → 原文高亮
间隔重现才能长期保留采纳过的认知隔几天回来考你一次；被新证据挑战时主动提醒

3. 怎么组织：四层金字塔，五个源汇到同一张卡

主题（约 11 个）沿用知识库现有主题
问题（每个主题 5–7 个）例：多 Agent 什么时候值得用？规则写多少合适？
认知卡（每个问题若干张）结论 · 成立条件 · 依据 · 可信度 · 时间线
证据（原始内容）X 长文 · 论文 · GitHub 项目 · 信息推荐里的讨论 · 产品雷达

关键变化有两个：

  • 中间加一层“问题”。上一轮试跑证明，只在“单条认知”层面去重，678 条只能合并 32 条（5%）。同一个问题下有很多相近但不同的说法，它们应该归到同一个问题下并列比较，而不是硬合并。问题是稳定的，答案在变，所以以问题为单位追踪最合适。
  • 五个信息源不再各看各的，而是各自承担一种证据角色。同一张卡上四盏灯，亮几盏一眼可见：
证据角色来自哪里回答什么怎么取
有人这么做X 长文、博客实践经验、做法、踩坑模型抽认知卡（已试跑）
有数据论文测量结果、对比实验已有标签（问题、方法、基准、基线），只对入选论文补抽结论
有人做出来GitHub 项目是否有实现、是否被采用已有标签加星标增长，不需要再抽
有人买单产品雷达是否有产品、融资、收入已有公司和事件表，直接关联
有人反对HN、Reddit、X 讨论争议点、反例只在已有卡的问题下找反对意见

这样论文、项目、产品这三个最大的库基本不用重新过模型，用现有标签挂到问题上就行；模型的钱主要花在长文抽取和归并上。

4. 怎么提炼：四步，每步都能回到原文

  1. 抽取。每篇长文抽认知卡，过价值门槛：有具体信息、可复用、不是常识。每条带原文引文，程序逐字核对。8 篇实测：准确率 85%，召回率 61%，引文 100% 可核对。
  2. 归位。每条认知挂到一个“问题”下。挂不上的攒到一定数量，由模型提议新问题，你确认后才加入骨架。
  3. 比对。在同一个问题内，和已有卡比较，分成四类：重复（只加来源数）、增益（并入时间线）、反驳（单独标出，不合并）、全新。38 篇实测：重复和增益的判断准确 92%，反驳的判断不可靠，需要人看。
  4. 综述。每个问题定期生成一段“现状”：共识是什么、分歧在哪、这段时间变了什么。每句话都必须引用卡片，没有引用的句子不允许出现。

三个视图，对应三种使用场景：

  • 变化简报（每天 15 分钟）。按问题分组，每组只显示新的、被加强的、被挑战的。顶部始终显示“进来多少条 → 归成多少条 → 你需要看多少条”，让你确信没漏，不必再去刷原始列表。
  • 主题地图（每周或想系统了解时）。主题 → 问题 → 每个问题一条状态：已有共识、有分歧、证据少、最近在变。可以一眼看出一个领域哪里已经定了、哪里还在吵。
  • 认知卡（想深入时）。结论、成立条件、四盏证据灯、时间线；点开看每个来源的原话，再点跳到原文高亮处（上一轮已做出对照页）。

6. 人怎么交互：四个动作，全部一键

动作你做什么系统接着做什么
表态每条变化点一下：已知 / 采纳 / 不信 / 想试“已知”的以后只计数不再展示；“采纳”的进入你的判断并安排回顾；“不信”的系统专门去找反例和数据；“想试”的进每日规划
先猜后看有分歧的问题，先选你的立场，再展开证据记录你的预测，证据出来后对比，这是最强的记忆方式
追问对任何卡或问题直接提问只基于库里的卡回答并附引用；答不了就说明缺什么证据，并加到采集关键词
回顾和产出每天回顾 3 张采纳过的卡；每周对 1–2 个问题写一句自己的判断判断写入知识库；之后有新证据挑战它时主动提醒你

表态同时解决了排序没有反馈的问题：现在赞踩是 0 次，因为对单条内容点赞没有意义；对一条认知说“已知”或“不信”是自然的动作，而且直接告诉系统你已经知道什么。

7. 怎么判断这套设计有没有用

指标现在目标说明
每天覆盖的内容量约 6 条500–1000 条简报背后挂的来源总数
每天花的时间未统计15–20 分钟超过就砍每屏条数
压缩比未知待实测进来条数 ÷ 需要看的变化条数；目前只有单主题 38 篇的数据，不能外推
“新的”占比—30% 以上太低说明在给你看已知的东西
每周形成的判断接近 03–5 条这是最终衡量吸收的指标
回顾答对率—70% 以上采纳的认知一周后还记得多少

8. 风险和还没验证的地方

  • 抽取会漏。召回率 61%，被漏掉的认知你看不到。缓解：每个问题保留“未归类原文”入口；每周抽 20 条人工看漏了什么。
  • 压缩比是假设。上一轮只做了单条认知去重，压缩 5%。“问题”这一层能压到多少还没测，这是试点要回答的第一个问题。
  • 反驳识别不准。模型判的“反驳”多数不成立，暂时只能列出来由你确认。
  • 综述可能编造。靠“每句必须带卡片引用、程序检查”来约束，没有引用就不显示。
  • 信息茧房。“已知”的被折叠后可能越看越窄。每期固定留 2–3 条来自你不看的主题或与你判断相反的内容。
  • 跨源关联没试过。论文、项目、产品挂到问题上的准确率未知，四盏灯目前只有第一盏有实测。
  • 成本。长文抽取 38 篇花了 0.23 美元，8,814 篇已分析长文全量约 50–60 美元；归并判断另算。

9. 建议的试点

  • 范围：只做一个主题“Agent 架构与上下文”，取最近两周的五个信息源。
  • 产出：一页真实的变化简报，加这个主题的问题地图，四盏灯全部接上真实数据。
  • 要回答的问题：两周内容进来多少条、压成多少条变化；你看完花多久；有没有你觉得重要但没出现的。
  • 不做：不改现有信息推荐和知识库页面，不写入正式库；先出静态页给你判断。
