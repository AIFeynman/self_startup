## 0. 目标与完成标准

P1 看的是「大公司 + 明星公司**发布了什么**」。这一期补「创业公司**赚了多少、怎么赚的、怎么长起来的**」，并按赛道横向比。

| # | 完成标准 | 怎么验 |
|---|---|---|
| C1 | TrustMRR 上 AI 相关、有收入的创业公司每天自动记一次 MRR / 近 30 天收入 / 订阅数，自己攒出时间序列（TrustMRR 页面只给 30 天图） | 连续 7 天跑完，任一公司能画出 7 个点；漏抓率 < 5% |
| C2 | 每家公司归到 1 个主赛道（+ ≤2 个副赛道），赛道页能按 MRR、增长率、新增 MRR 排序，并给出赛道汇总（总 MRR、中位增长、定价形态分布、渠道分布） | 抽 30 家人工核对赛道，准确率 ≥ 85% |
| C3 | 重点公司（Top / 增长异动 / 手动关注）有「生意拆解卡」：收入、商业模式、产品功能、获客渠道、做对了什么、可抄的打法、风险，事实带来源和日期，推测标注 | 卡片校验同 P1：节齐全、有链接、有日期 |
| C4 | Product Hunt 每日榜（Top 10）有一段「榜单解读」：按赛道归类、共同点、值得试的 1–2 个 | 每天 1 篇，10 点前生成 |
| C5 | 收入异动变成事件进 P1 的变化流（里程碑、暴涨 / 暴跌、挂牌出售），和产品发布放在同一条时间线上看 | 事件流能按「收入」类型筛 |

## 1. 现状：已有什么，缺什么

已有（不用重做）：
- **信息推荐 `_feed_sources.fetch_trustmrr`**：已能解析 TrustMRR 页面里的 RSC 数据（`currentMrr`、`currentLast30DaysRevenue`、`cachedGrowth30d`、`marketingChannels`、`aiEnrichment` 里的价值主张 / 痛点 / 定价…），但**只抓「近 30 天挂牌出售」的**，且每次覆盖，不留历史。主库里目前 0 条 TrustMRR 条目（源没开或失败，待查）。
- **`_feed_sources.fetch_producthunt`**：PH 官方 API，主库已有 61 条，有票数，没有当日排名。
- **`_feed_product`**：给产品条目生成 5 项一句话分析（收入 / 模式 / 定位 / 价值 / 痛点），存在 `feed_items.extra.pa`。
- **产品雷达 P1**：公司 / 信息源 / 事件 / 解读卡 / 公司时间线 / 分级 / 只追加的分析表。

缺：
1. **收入时间序列**——没有按天落库的指标表，ARR 变化看不出来；
2. **创业公司实体**——feed 条目是一次性的，没法「关注一家公司、看它几个月的变化」；
3. **赛道**——没有统一分类，也就没法横向比；
4. **增长渠道**——只有 TrustMRR 给的渠道标签，没有「怎么做起来的」拆解；
5. **PH 排名解读**——只有单条，没有每天一张榜的整体判断。

## 2. 数据源与可信度分级

每个数字都带 `grade`，页面上用不同样式显示，解读时不能混着用：

| grade | 含义 | 来源 |
|---|---|---|
| `verified` | 支付渠道（Stripe / RevenueCat / Paddle…）直连验证 | TrustMRR |
| `reported` | 公司或创始人公开说的（官博、X、采访、融资新闻） | P1 的事件流 + 信息推荐里的 X / HN / 博客，新增类型 `metric` 抽数字 |
| `estimated` | 第三方估算（流量、排名推算收入） | 本期不做，只留字段 |

| 源 | 抓什么 | 频率 | 说明 |
|---|---|---|---|
| TrustMRR 首页排行榜 + 分类页 + `/acquire` | 所有有收入的公司的 MRR / 30 天收入 / 增长 / 是否在售 | 每天 1 次 | 复用 `rsc_objects` 解析；按分类页翻全 AI 相关分类 |
| TrustMRR `/startup/<slug>` | 价值主张、痛点、受众、定价、渠道、市场标签、创始人 X、成立时间 | 新进名单时读一次，之后 30 天刷新 | 每天最多 50 个详情页，4 并发 |
| Product Hunt API | 当日 Top 20：排名、票数、评论数、标签、Maker | 每天 1 次（太平洋时间次日凌晨，榜单定格后） | 复用已有 token |
| 公开 ARR 报道 | 「Lovable 达到 $X ARR」这类 | 跟着 P1 每 10 分钟一轮 | P1 分类时多一个类型 `metric`，结构化抽 `{metric, value, period, date}`，数字必须在原文出现（同定价校验） |
| BizPeel | 不抓 | — | 它的报告是付费内容，默认只在公司页放「去 BizPeel 看」链接；你自己看过觉得有用的，可以粘贴进公司页的「笔记」 |

## 3. 对象模型（在 P1 表上加）

```
intel_company  + kind   TEXT  -- lab（大厂/模型厂）| native（明星 AI native）| startup（创业公司，本期新增）
               + track  TEXT  -- 主赛道 slug
               + tracks TEXT  -- 副赛道 JSON
               + watch  INT   -- 1 = 重点关注（出生意拆解卡、进变化流）；0 = 只记指标
               + ext    TEXT  -- JSON：trustmrr_slug、ph_slug、website、founder_x、bizpeel_url…

intel_metric   (company_id, date, metric, value, grade, source, url, created_at)   -- 只追加
               metric：mrr | revenue_30d | total_revenue | subscriptions | arr | ph_rank | ph_votes | for_sale | asking_price
               唯一键 (company_id, date, metric, source)，同一天重复抓取覆盖当天值

intel_track    (slug, name, parent, description, keywords)   -- 赛道表，可在页面上改
intel_profile  (company_id, content, quality JSON, inputs_hash, job_id, created_at)  -- 生意拆解卡，只追加
intel_ph_day   (date, items JSON, analysis, job_id)  -- PH 每日榜 + 解读
```

名单规模：TrustMRR 上 AI 相关 + 近 30 天收入 > 0 的，估计 500–1500 家，全部 `watch=0` 只记指标（不调模型，几乎零成本）；`watch=1` 的才花模型。

## 4. 赛道

**默认：固定赛道表 + 模型归类 + 人工可改。** 起始 16 个（可在页面上增删）：

编码 Agent / AI 编程工具 · 设计与 UI 生成 · 图像生成 · 视频生成与剪辑 · 语音 / 音乐 · 写作与内容 · 社媒运营与营销 · 销售与 GTM · 客服与对话 · 通用 Agent / 自动化 · 知识与研究 · 教育与学习 · 电商工具 · 开发者基础设施（API / 数据 / 评测） · 垂直行业（法律 / 医疗 / 金融 / 房产…） · 消费娱乐（陪伴 / 游戏 / 社交）

归类：输入 = 名称、简介、TrustMRR 的市场标签 / 价值主张 / 受众，DeepSeek 批量（20 家一批）给主赛道 + 副赛道 + 一句理由；TrustMRR 标签能直接映射的（如 `Social Media` → 社媒运营）不调模型。人工改过的不再自动覆盖。

**赛道页**（`#intel/t/<slug>`）：
- 汇总：公司数、总 MRR 及 30 天变化、增长中位数、MRR 分布（<1k / 1–10k / 10–100k / >100k）；
- 排行：MRR、增长率、新增 MRR 三个 tab（同 BizPeel 的「revenue movers」）；
- 形态：定价（订阅 / 按量 / 买断 / 混合）分布、获客渠道分布（来自 TrustMRR `marketingChannels` + 拆解卡）、B2B / B2C；
- 本周变化：新进入的公司、挂牌出售的公司（往往意味着增长到顶或创始人转向）、相关 PH 上榜产品、P1 里同赛道大厂的发布（大厂进场是小公司最大的风险）；
- 赛道小结：每周一次 DeepSeek 写 5 条「这个赛道现在在发生什么」，只基于以上数据，数字原样引用。

## 5. 生意拆解卡（watch=1 的公司）

结构对齐 Yihui 那篇的两件事 + BizPeel 的四个视角，后台 Claude 任务（standard 档，可联网），每天上限 `intel.profiles_per_day`（默认 10）：

```
## 收入        verified 数字 + 我们自己攒的曲线（第一次只有 1 个点就写 1 个点），reported 的单独列
## 卖什么      产品功能、交付的结果、和替代方案比的差异
## 怎么收钱    定价、订阅 / 买断 / 按量、免费层设计、客单价推算（标【推测】）
## 客户从哪来  渠道拆解：SEO（有没有免费小工具页引流）、X / 社媒（创始人账号、创作者合作）、PH / 社区发布、
               付费投放、产品内传播；每条带证据链接
## 做对了什么  定位、时机、定价、发布节奏里可以学的
## 可抄的打法  如果我在这个赛道做，具体照做的 2–3 步
## 风险        大厂进场（链接 P1 同赛道事件）、平台依赖、增长是否靠一次性爆点
```

触发：手动关注；进入赛道 MRR Top 10；30 天增长 ≥ 100% 且 MRR ≥ $1k；首次挂牌出售且 MRR ≥ $5k。同一家 30 天内不自动重做（数字变化大时例外）。

## 6. 收入异动 → 事件（进 P1 变化流）

指标每天落库后跑确定性规则，不调模型：

| 事件 | 规则 | 级别 |
|---|---|---|
| 收入里程碑 | MRR 首次跨过 $10k / $50k / $100k / $1M | $100k 起 A，其它 B |
| 暴涨 | 30 天增长 ≥ 100% 且 MRR ≥ $3k | B（MRR ≥ $30k 时 A） |
| 暴跌 | 30 天下降 ≥ 40% 且 MRR ≥ $5k | B |
| 挂牌出售 | 新出现在 `/acquire` | MRR ≥ $10k B，否则 C |
| 公开 ARR | P1 抽到的 `metric` 事件 | 走 P1 分级（T1/T2 公司 A） |
| PH 上榜 | 日榜 Top 3 且是已在名单里的公司 | C（只进时间线） |

B 级及以上的公司事件，第一次出现时把公司标成 `watch=1`，进而出拆解卡。

## 7. Product Hunt 每日榜解读

- 每天 1 次拿当日 Top 20，按赛道归类（复用第 4 节）；
- 一次 DeepSeek 调用写解读：今天各赛道上了什么、共同趋势、哪些只是换皮、值得亲手试的 1–2 个（给理由）、和 TrustMRR 已验证赚钱的同类对照（有就列名字和 MRR）；
- 连续 7 天的榜单可以看「赛道热度」变化（上榜数 × 票数），并入赛道页。

## 9. 和判断力训练（D5）的接口

拆解卡的「可抄的打法」和赛道小结里，各留一个可验证预测位（如「X 在 60 天内 MRR 过 $20k」），到期自动拿 `intel_metric` 判对错——这是 D5 最容易自动打分的一类题，建议 D5 从这里起步。

## 11. 成本与风险

- 成本：每日快照不调模型；归类首轮约 1000 家 / 20 一批 ≈ 50 次 DeepSeek，之后只算新增；拆解卡每天 ≤ 10 张 Claude 任务；PH 解读每天 1 次 DeepSeek。
- TrustMRR 页面结构变化：解析失败时记 `last_err`、页面告警，不写空值（空值会被当成暴跌）。
- 访问频率：每天首页 + 分类页 + ≤ 50 个详情页，加随机间隔，遵守 robots。
- 口径：TrustMRR 只算连上的支付渠道（有公司注明大部分收入走别的平台）、自愿上榜有幸存者偏差——页面和卡片里都写明「verified 只代表连上的渠道」。
- BizPeel 内容是付费的，不抓不转载。

## 12. 需要你拍板的问题

1. **跟踪范围**：TrustMRR 上 AI 相关、有收入的全部记指标（默认），还是只跟手选名单？
2. **BizPeel**：只放链接 + 你手动粘贴（默认），还是你有账号想接它的数据？
3. **赛道**：固定 16 个起步 + 模型归类（默认），还是自动聚类出赛道？
4. **渠道拆解深度**：拆解卡用 Claude 联网查（默认，每天 ≤ 10 张），还是只用 TrustMRR 字段 + DeepSeek 推测（便宜很多但浅）？
5. **大一点的 AI 创业公司**（Lovable、Cursor、Genspark 这类没上 TrustMRR 的）：用公开报道的 ARR（reported）一起放进赛道比（默认放，但和 verified 分开显示），还是不放？

### 拍板结果（2026-11-01）

1. 跟踪范围：TrustMRR 上 AI 相关、有收入的全部记指标，重点的才出拆解卡。
2. BizPeel：未单独问，按默认——只放链接 + 手动粘贴，不抓。
3. 赛道：固定 16 个起步 + 模型归类，页面可改。
4. 渠道拆解：Claude 联网查，每天 ≤ 10 张。
5. 公开报道 ARR：放进赛道，标 reported，和 verified 分开显示、不混算汇总。
